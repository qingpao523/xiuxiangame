# 真人 Playtest 设计文档 / 规格（GAME-XIUXIAN《封神·放置修仙》）

> 作者：严守真（quality-lead · QA 主理人）
> 日期：2026-08-18
> 关联：评测汇编 §4 风险清单 P0 首项「无真人 Playtest，发布体验未知」
> 定位：**让人去玩并打分的规格文档**，不是 AI 自测脚本。把"好不好玩"从假设变证据。
> 验收纪律：沿用 `CLAUDE.md` #6「验收标准先行、≥95 通过」惯例。

---

## 0. 背景：为什么需要这份文档

| 来源 | 结论 |
|---|---|
| 多 Agent 六维评估（QA 行） | 纪律 PASS／体感 CONCERNS／可玩放行 **FAIL**——「做完没玩过」 |
| Playwright 加速全弧泡测 | 工程侧 QA **PASS**：启动稳、全弧可通关、0 报错、0 软锁（自动化证据） |
| 评测汇编 §4 风险清单 | 🔴 P0：无真人 Playtest，发布体验未知（严守真列为首项风险） |

**核心矛盾**：机器人（playtest.mjs）已证「能跑通、能赢、不崩」，但**不评估"好不好玩"**（其报告 §5 已诚实声明）。
本项目 100 分验收验证的是"实现存在且设计上对"，而 **feel / 好玩 / 节奏 / 叙事沉浸被默认满分**——这正是评测一致点名的真问题。

**本方案目标**：把"好玩 / 手感 / 节奏 / 叙事沉浸"拆成**可勾选、可记录、可打分**的真人走查清单，使"体验门控"从无法验证变为可验证、可回归、可放行。

> 重要：本方案是**规格**，不是测试执行结果。它填补的是"证据采集方法缺失"，不取代"证据本身"。执行并达标后，P0 风险才解除。

## 2. "像画卷吗"体验评分卡（100 分制，≥95 通过）

> 把 `design/6.0` 的三层反馈哲学（微文案 / 小仪式 / 大画卷）与三原则（留白 / 渐显 / 气韵）转成可打分维度。
> 沿用 `CLAUDE.md` #6 惯例：**满分 100，≥95 通过**；85–95 需打磨重测；<85 打回重做。

评分：每项 0–5 分（0=完全不符，5=完美落地）。得分 = Σ(单项分/5 × 权重)。

| 维度 | 设计依据（6.0） | 评分 0–5 | 权重 | 单项合格线 | 现象 / 备注 |
|---|---|---|---|---|---|
| **微文案**：反馈读起来是"感受"而非"数字"（"+500 道行"→"你听见了风"） | 6.0 总纲 / §七「反馈从数字改为气韵」 | | 12 | ≥4 | |
| **小仪式**：关键节点有"仪式感"（首吐纳、破劫、法宝择主）而非按钮 | 6.0 §一第四息、§七 | | 12 | ≥4 | |
| **大画卷**：世界像卷轴展开，山河图有雾/悬念/渐显 | 6.0 总纲 / §二（地图是可探索空间） | | 12 | ≥4 | |
| **留白**：存在"什么都不发生"的时刻，沉默/等待是体验一部分 | 6.0 三原则① | | 12 | ≥4 | |
| **渐显**：世界随玩家走动才亮，未至之地只有雾与悬念 | 6.0 三原则② / §二（榜文是谜非进度条） | | 12 | ≥4 | |
| **气韵**：反馈是"气韵"而非数字，数字在底层算、玩家读到感受 | 6.0 三原则③ | | 12 | ≥4 | |

## 3. Bug 分级体系（S0–S3）

> 弥补评测指出的"无 Bug 分级体系"缺口。结合 `CLAUDE.md` #6 放行纪律。

| 级别 | 名称 | 定义 | 触发条件（示例，引用真实风险点） | 放行政策 |
|---|---|---|---|---|
| **S0** | 阻塞 Blocker | 阻断主线 / 崩溃 / 数据损坏 / 无法启动 | • 旧档（Block E）打开白屏或崩溃<br>• 首破劫后卡死无法继续（软锁，Playwright 未触发但需人防）<br>• 存档损坏/丢失<br>• 游戏无法启动 | **不放行**：必须修复或提供 workaround 后方可进体验门 |
| **S1** | 严重 Critical | 核心玩法受损但可绕行；数值严重异常；存档/付费风险 | • 首破劫手工模式默认且无提示 → 新手误以为"打不动"必败（playtest-report §3.1）<br>• 单次行动弹窗连发 >1 关键模态，造成阻断（违 CLAUDE#4）<br>• 战力倒挂/数值严重异常<br>• 离线收益为 0 或溢出 | **不放行**：修复前不得放行 |
| **S2** | 一般 Major | 体验明显受损，非核心路径 | • 微文案错字/逻辑矛盾<br>• 某关键反馈缺失（如升重无演出）<br>• 移动端字号过小（eval P2）<br>• 某机缘无保底触发<br>• 引导不可跳过 | **可带伤上线**：登记并排期，不阻断放行 |
| **S3** | 建议 Minor | 主观打磨、锦上添花 | • 留白不足 / 气韵文案可更雅<br>• 美术细节<br>• 节奏微调<br>• 可选音效建议（**eval：音频三端皆空，当前为系统性缺口非单 Bug**） | **排期**：纳入后续版本 |

**处理时效建议**：S0 即时响应（当日）；S1 当版本修复；S2 登记并排期；S3  backlog。
**编号规则**：`BUG-<块字母><序号>-<S级>`，如 `BUG-C1-S1`（首破劫手工无提示）。

## 7. 边界声明：AI 不能替代真人手感

> **本方案是"让人去玩并打分"的规格，不是 AI 自测。** 以下为明确边界。

**7.1 本方案能做什么**
- 把"好玩 / 手感 / 节奏 / 叙事沉浸"拆成可勾选、可记录、可打分的结构化清单。
- 定义放行门控的"采集方法"与"评分阈值"（≥95 画卷分、S0/S1 归零）。
- 标注 Playwright 已覆盖与未覆盖的边界，避免重复劳动。

**7.2 本方案无法覆盖、仍需真人主观验收的点**
1. **主观爽感**：突破/渡劫/收菜的"爽"无法由脚本判定（playtest-report §5 已声明）。
2. **手感与节奏**：微决策密度、零干等、每日"领奖感"是时间感知，需真人。
3. **叙事沉浸 / 共鸣**：榜文谜面、留白、气韵、世界观即参与——纯主观。
4. **手工战斗难度体感**：首破劫手工胜率（脚本强制自动，C1 必真人）。
5. **真实节奏数值平衡**：脚本注入资源+快进已破坏此验证（D1 必真人）。
6. **美术气质 / 声音**：评测指出音频三端皆空、画卷细节待磨——需真人（与听觉）验收。
7. **移动端体感**：触控、窄屏、reduced-motion、webview 生命周期（F1–F7）。
8. **旧玩家情感 / 旧档兼容**：从未被脚本测过（E1–E6）。

**7.3 质量门性质**
- 本方案给出的是**建议性门控（advisory）**。最终是否放行由主理人（用户）决定。
- `playtest.mjs` 的角色是"工程侧冒烟/全弧回归"，不是"体验验收"。
- 本方案执行并达标（≥95 画卷分 + 关键 S0/S1 归零 + A–F 关键项通过）后，**评测 §4 P0「无真人 Playtest」风险才解除**；在此之前，发布体验仍是未知。
