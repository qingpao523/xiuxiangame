# 7.4 开局种族开放限定验收标准 v0.1

> 任务：开局「择跟脚」种族选择，当前**只开放人族、妖族**；其余 7 个种族（先天生灵/麒麟/巫/魔/龙/凤/鸿蒙凶兽）显示「暂未开放」且不可选择。
> 源头：design/6.0 §四（首期 4 选 1 原指 人/妖/先天生灵/麒麟；巫/魔/龙/凤/鸿蒙为带 unlock_condition 的后期种族）。本任务为产品分阶段上线决策，将开局进一步收窄至 人/妖 2 选 1。
> 流程：CLAUDE.md#6 验收先行 → 实现 → 逐项打分（≥95 通过，<95 打回）。

---

## 一、背景与问题（第一性原理）

- 现状缺陷：`web/js/ui.js` `renderRaceChoicePopup`（~663）把 `race_table` 全部 9 个种族渲染成**可点击按钮**；`race_table.json` 的 `unlock_condition` 字段仅为文案，代码从未强制。即先天生灵/麒麟/巫/魔/龙/凤/鸿蒙当前皆可直接选——「跟脚一选定终身」的承诺被绕过，且后期种族提前暴露破坏节奏。
- 缺失的细节设定（本文件补齐）：
  1. 用**显式数据字段**标记开放/锁定（不靠隐式判断），支持未来逐个解锁（仅改字段，不动逻辑）。
  2. 锁定种族**仍可见**（世界观铺陈 + 钩子），但视觉置灰 + 「暂未开放」徽章 + 不可点。
  3. **逻辑层强制**：`Game.chooseRace` 拒绝锁定种族（防绕过）。因 `reincarnate()` 会重置 `race_id` 重开种族选择，锁定必须在每次选择都生效，不能只靠 UI。
  4. 锁定文案分层：统一「暂未开放」前缀 + 每族一句主题钩子（`lock_hint`），保留既有 `unlock_condition` 作为未来解锁路径记录。

## 二、设计（细节设定）

### 数据层（web/data/race_table.json）
- 每行新增两字段：
  - `open`（boolean）：`human`/`yao` = `true`；其余 7 族 = `false`。
  - `lock_hint`（string）：锁定种族的主题钩子（开放族可省略）。
- 保留既有 `unlock_condition`（巫/魔/龙/凤/鸿蒙）作为未来解锁路径记录，本期不实现其解锁逻辑。
- 未来解锁某族 = 将其 `open` 改 `true`，无需改任何代码。

### 逻辑层（web/js/game.js）
- `chooseRace(raceId)`：在既有校验后增加 `if (!row.open) return;`（拒绝锁定种族，纵深防御）。
- 新增辅助 `Game.isRaceOpen(raceId)`（读 `race_table.open`，缺省视为锁定）供 UI/测试复用。

### 表现层（web/js/ui.js renderRaceChoicePopup）
- 开放族：照常渲染，可点击 → `Game.chooseRace`。
- 锁定族：
  - 按钮加 `disabled` + `locked` class（置灰、不可点）。
  - 名称行追加「暂未开放」徽章。
  - 副文案显示 `lock_hint`（主题钩子），点击无反应或提示「该跟脚暂未开放」。
- 9 族全部列出（开放 2 + 锁定 7），顺序按表序。

### 锁定文案（lock_hint，主题钩子）
| 种族 | lock_hint |
|---|---|
| 先天生灵 | 大道遗泽尚未降临——伴生灵宝，静候有缘。 |
| 麒麟 | 瑞兽未醒。福缘深厚者，大劫后方现。 |
| 巫族 | 盘古血脉沉睡，待转世道痕深厚者唤醒。 |
| 魔族 | 天魔不灭，须劫气缠身者方可承其血脉。 |
| 龙族 | 真龙潜渊，待巡行陈塘者感应潮汐。 |
| 凤族 | 涅槃之火未燃，待火系圆满者引燃。 |
| 鸿蒙凶兽 | 混沌未开，需遍历万族图鉴者方得窥。 |

## 三、验收评分维度（打分制，每项 1–5 分，≥95 通过）

| 维度 | 权重 | 5 分标准 | 1 分标准 |
|---|---|---|---|
| 开放限定正确性 | 30% | 仅 human/yao 可选；其余 7 族逻辑层 + UI 双重不可选 | 锁定族仍可选/可提交 |
| 锁定呈现 | 20% | 锁定族可见 + 置灰 + 「暂未开放」徽章 + lock_hint 钩子，9 族全列 | 无徽章/直接隐藏/无钩子 |
| 防绕过（纵深防御） | 20% | chooseRace 拒绝锁定族；转世重开选择后锁定仍生效 | 仅 UI 禁用，逻辑可绕过 |
| 数据机制完整性 | 12% | 显式 `open`+`lock_hint` 字段；未来解锁仅改字段；保留 unlock_condition | 靠隐式判断/写死种族名 |
| 不破坏现有 | 10% | human/yao 流程不变；既有种族天赋（qilin 机缘/xiantian 灵宝/yao 吞噬/human 折扣）代码不受损 | 破坏开局流/既有天赋失效 |
| 代码质量 | 8% | 复用 DataManager/既有样式；无写死；node --check + 审计通过 | 写死/重复/语法错 |

### 硬性否决（任一触发即不通过）
1. 锁定种族仍能被选为 `race_id`（逻辑或 UI 任一可绕过）。
2. 人族/妖族正常开局流程被破坏。
3. 锁定仅靠 UI 置灰、`chooseRace` 无逻辑强制（转世后即可绕过）。

## 四、验证方式
- `node --check` 全 `web/js/*.js`；`node audit_integrity.js` + `node audit_completeness.js` 零问题。
- 单元/集成测试（Node harness）：仅 human/yao `isRaceOpen` 为真；`chooseRace` 对锁定族不写入 `race_id`；对开放族正常写入。
- 手工核对 `renderRaceChoicePopup` 渲染 9 族、锁定族 disabled + 徽章。

- v0.1：验收标准 + 细节设定已定。待实现 → 打分。
