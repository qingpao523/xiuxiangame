## 一、三层容器总览

```
① 大地图层（overworld 拓扑）   封神山河图 = 唯一真世界，四大部洲区块（南赡部洲伐纣主脊柱）
        ↓ 点按节点
② 单地图层（空间纵深）         每张图 = 探索点群 + 遭遇池 + Boss群
        ↓ 探索点/遭遇/Boss
③ 投放层（玩法入口）           Boss聚合 / 镇魔塔挂点 / 流派机缘tag（预留）
```

设计原则：
- **单一数据源**：map_table 是地图唯一权威表；山河图视觉层（world-map.js）从 map_table 读取，不再各存一套。
- **容器先于内容**：本批只搭骨架 + 补后6图基础行动/探索点；Boss/镇魔塔/流派是后续"投放"，不在本批产新Boss内容。
- **复用既有机制**：探索点驱动直接沿用 design/6.5（discover_after 门槛）+ 6.6（trigger_event/unlock_encounter），不另造轮子。

### 3.6 gate 逻辑（unlock-manager.js getAvailableMaps）

```
unlocked(map) = realm ≥ map.unlock_realm            // 主锁（已有）
             && (map.prev_map == null               // 前置链（F3弱锁）
                 || unlocked(map.prev_map))
             && (map.continent == "南赡部洲"          // 部洲开放（分支图额外门）
                 || continentUnlocked(map.continent))
```
部洲开放说明：南赡部洲＝主脊柱（境界门即开）；东胜神洲/西牛贺洲/北俱芦洲/须弥昆仑中枢＝分支，按境界 + 特定条件（如势力/卷进度）开放（具体阈值 M1 定）。弱锁说明：因境界已隐式排序，prev_map 极少实际阻拦；其价值在**显式路径**与未来同境界多图排序。卡玩家风险低（见§九）。

## 四、② 单地图层设计（空间纵深）

### 4.1 每张图 = 探索点群 + 遭遇池 + Boss群

```
驻留地图(current_map_id)
   → 游历行动（action_table 该图行）结算
        → map_explores[map_id]++
        → 触发探索点发现（discover_after 门槛，6.5）
             → 发现点可 trigger_event（6.6事件）/ unlock_encounter（6.6遭遇）
        → 遭遇池抽取（_setupActionExtras，按 map_id + requires_point 过滤）
   → Boss群（按 boss_table.map_id 聚合，见§五）
```
