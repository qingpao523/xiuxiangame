# 5.1 内容验收评分标准 v0.1

> 配套 `design/5.0`。每批数据产出后按本标准逐表打分，≥95 分通过，<95 分的维度返工。

---

## 一、评分总则

- 满分 100 分，由 8 个维度加权。
- 每维度 0-5 分，乘权重后累加。
- **≥95 分：通过。**
- 90-94 分：列出扣分项，修复后复验。
- <90 分：该表整体返工。
- 任何硬性否决项触发：直接不通过，不论总分。

---

## 二、评分维度

| # | 维度 | 权重 | 5 分标准 | 3 分标准 | 1 分标准 |
|---|------|------|----------|----------|----------|
| 1 | 数据完整性 | 15% | 所有必填字段齐全，JSON 可解析，ID 无重复/断号 | 个别可选字段缺失 | 必填字段缺失或 JSON 格式错误 |
| 2 | 数值锚定 | 15% | 伤害/奖励/消耗严格锚定当前境界 base_daoxing_per_min 与 combat_power_base，曲线平滑无断层 | 大致合理但有 1-2 处跳跃 | 数值与境界脱节，前期溢出或后期不足 |
| 3 | 封神锚点 | 15% | 每条内容挂接≥1 个封神原著元素（人物/法宝/阵法/典故），且挂接准确不牵强 | 有锚点但部分牵强 | 泛化修仙，无封神辨识度 |
| 4 | 叙事文案 | 15% | 每条叙事≥3 句，有场景+动作+情绪；对话有人物性格；禁止"你获得了X"式干巴文案 | 有文案但部分干巴 | 纯数据无文案 |
| 5 | 选择与后果 | 10% | ≥50% 事件有 2+ 选择，选择有实际数值/路线后果，且后果与封神价值观挂钩 | 有选择但后果雷同 | 无选择，纯线性 |
| 6 | 解锁节奏 | 10% | 内容按境界均匀分布，无空窗（任何 3 重区间内≥2 条新内容），无堆积（单重≤4 条） | 大致均匀但有 1 处空窗或堆积 | 大段空窗或全部堆在一处 |
| 7 | 战斗设计 | 10% | 卡牌/Boss 有明确战术定位（爆发/持续/控制/自损），同系内有递进，跨系有克制 | 有定位但递进不明显 | 所有卡牌/Boss 同质化 |
| 8 | 一致性 | 10% | 与现有数据表无矛盾（ID/命名/境界/资源），新增内容不破坏已有平衡 | 有 1 处小矛盾 | 多处矛盾或破坏已有系统 |

## 三、硬性否决项（触发即不通过）

1. JSON 解析失败或 ID 冲突。
2. 任何术法/卡牌/Boss 无封神锚点（纯泛化修仙命名）。
3. 事件文案 <2 句。
4. 数值出现"前期神器后期垃圾"（初阶伤害 > 中阶伤害）。
5. 解锁条件与 realm_table 矛盾（如引用不存在的 realm_id）。
6. 新增内容使前 30 分钟节奏变慢（违反 design/1.9）。

## 四、逐表检查清单

### 4.1 spell_table 扩展

- [ ] 每门术法有：spell_id, spell_name, spell_school, tier, unlock_realm, card_id, card_base_damage, card_damage_per_level, card_element, card_special, upgrade_costs, lore_text, visual_keywords, advanced_names
- [ ] 同系 5 阶伤害严格递增（阶 n+1 base > 阶 n base + 阶 n per_level×5）
- [ ] 每系有独立战斗风格标签（burst/dot/break/true_risk/self_harm）
- [ ] lore_text ≥2 句，含封神来源
- [ ] unlock_realm 在 realm_table 中存在
- [ ] upgrade_costs 法力消耗锚定当前境界 base_mana_per_min（单次升级 ≤ 30 分钟法力产出）

### 4.2 boss_table 扩展

- [ ] 每个 Boss 有：boss_id, boss_name, unlock_condition, map_id, recommended_power, reward_daoxing, reward_mana, reward_items, lore_text, victory_text, visual_keywords, mechanics（新增字段：描述特殊机制）
- [ ] recommended_power 锚定解锁境界 combat_power_base × 0.8~1.2
- [ ] reward_daoxing 锚定解锁境界 base_daoxing_per_min × 20~40（即 20-40 分钟产出）
- [ ] lore_text ≥3 句，含封神来源与战斗场景
- [ ] 每个 Boss 有≥1 个特殊机制（非纯数值碾压）

### 4.3 encounter_table 扩展

- [ ] 每条有：encounter_id, map_id, encounter_name, encounter_type(battle/choice/gather/narrative), unlock_condition, weight, text, battle_config/choices/gather_reward
- [ ] 每图 6-10 种，类型分布：战斗 40% / 选择 25% / 采集 20% / 叙事 15%
- [ ] text ≥3 句
- [ ] 战斗遭遇有 enemy_name + enemy_power_ratio + intent_pool
- [ ] 选择遭遇到少 2 个选项，选项有实际数值差异

### 4.4 event_table 扩展

- [ ] 每条有：event_id, event_name, source, unlock_condition, weight, daily_limit, lifetime_limit, title, body, choices, visual_keywords
- [ ] body ≥3 句（场景+事件+情绪/悬念）
- [ ] ≥50% 有 2+ choices
- [ ] choices 的 result 有实际资源/状态差异
- [ ] unlock_condition 引用的 realm_id/flag 在系统中存在
- [ ] 按章节分布均匀（卷一 15 / 卷二 20 / 卷三 15 / 卷四 25）

### 4.5 companion_table 扩展

- [ ] 每位有：companion_id, name, title, glyph, unlock_realm, faction_affinity, stages(3-5), bond_card, bond_passive_desc, bond_text
- [ ] 每 stage 有 title + condition + text
- [ ] stage.text ≥4 句，有对话（用「」），有人物性格
- [ ] bond_card 在 CARD_DEFS 中有对应定义
- [ ] bond_passive_desc 数值合理（5-15% 区间）
- [ ] 人物登场按境界递进，无两位同境界同条件登场

### 4.6 战斗卡牌（CARD_DEFS）

- [ ] 每张有：id, name, kind, element, target, base_damage, damage_per_level, special, special_params, text(level, mult, state)
- [ ] 同系卡牌有明确递进（伤害/特效复杂度）
- [ ] 跨系有克制关系（雷克妖、火克多体、剑克单Boss、魂克高防、劫高风险高收益）
- [ ] text 函数输出≥1 句战斗文案
- [ ] 资源卡（功德/劫气）消耗量与当前经济平衡

### 4.7 treasure_table 扩展

- [ ] 每件有完整字段（同现有 9 件格式）
- [ ] 封神来源明确（origin_desc + fengshen_relation）
- [ ] 技能有战斗/收益实际效果
- [ ] level_growth 5-8 级，消耗递增合理
- [ ] 品质与解锁境界匹配

### 4.8 pill_table（新表）

- [ ] 每条有：pill_id, pill_name, unlock_realm, cost, effect, effect_duration, daily_limit, lore_text, fengshen_anchor
- [ ] cost 锚定当前境界法力产出（≤60 分钟产出）
- [ ] effect 有明确数值，不模糊
- [ ] lore_text ≥2 句

## 五、验收流程

```
产出数据 → JSON 格式校验 → 逐表按清单检查 → 8 维度打分 → 硬性否决项检查
  ↓ ≥95 分                                              ↓ <95 分
通过，写入 devlog                                    列出扣分项 → 修复 → 复验
```

```

### 扣分项与修复记录
```
