## 三、硬性否决项（触发即打回）

1. 提案与 CLAUDE.md 不可违背条款（前 30 分钟守则/弹窗克制/封神锚点/验收先行）直接冲突且无论证。
2. 未读仓库实际文件，现状盘点为臆测。
3. 提案需要推翻"数据为体、画面为用"架构或全量重写引擎。
4. 修改了任何代码/数据文件（本批提案必须是纯思考稿）。
5. 照抄石海原话当方案，没有与本作架构/品类结合的转译。

## 四、提案文档统一结构（各轨必须遵守）

```
0. 现状盘点（引用文件证据）
1. 石海的标准（对应访谈原观点）
2. 差距分析（现状 vs 标准，具体到哪一环出戏/缺失）
3. 改善提案（分三档：零代码起步 → 低代码 → 系统级；含依赖与次序）
4. 风险与取舍（含与 CLAUDE.md 守则的对照结论）
5. 验收钩子（未来实现时的可核对标准）
```

## 五、整体性排查（全部提案完成后执行）

1. 六轨之间是否互相矛盾（如 21.3 终局与 21.4 道友、21.2 气韵化与 21.1 破劫的先后）。
2. 合并后是否与 CLAUDE.md 八条守则、6.0 画卷三原则、破劫思考稿既有结论冲突。
3. 合并后是否偏离石海核心点：不出戏为前提、回到原点、疲劳点警惕、结构高于实现、质量唯一标准。
4. 输出：冲突清单 + 建议执行次序（对照既有主线：6.0 画卷 → 破劫 → 20.0 网游化的次序主张）。
