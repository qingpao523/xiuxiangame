## 一、三层容器总览

```
① 大地图层（overworld 拓扑）   封神山河图 = 唯一真世界，9节点推进链
        ↓ 点按节点
② 单地图层（空间纵深）         每张图 = 探索点群 + 遭遇池 + Boss群
        ↓ 探索点/遭遇/Boss
③ 投放层（玩法入口）           Boss聚合 / 镇魔塔挂点 / 流派机缘tag（预留）
```

设计原则：
- **单一数据源**：map_table 是地图唯一权威表；山河图视觉层（world-map.js）从 map_table 读取，不再各存一套。
- **容器先于内容**：本批只搭骨架 + 补后6图基础行动/探索点；Boss/镇魔塔/流派是后续"投放"，不在本批产新Boss内容。
- **复用既有机制**：探索点驱动直接沿用 design/6.5（discover_after 门槛）+ 6.6（trigger_event/unlock_encounter），不另造轮子。

### 3.2 数据模型：map_table 扩字段（向后兼容）

现有字段保留（map_id/sort_order/map_name/unlock_realm/recommended_power/daoxing_per_min/mana_per_min/drop_table/boss_id/lore_anchor/narrative_desc/entry_text/visual_keywords/background_asset_key/drop_lore_map）。**新增**：

| 新字段 | 类型 | 含义 | 示例 |
|---|---|---|---|
| prev_map | string\|null | 前置节点（F3链） | "map_003" |
| region | string | 区域/卷名 | "卷四·西岐烽火" |
| volume | int | 卷序号 1-8 | 4 |
| node_kind | string | 山河图节点图标类型 | "city"/"array"/"seal"/"dao" |
| wx, wy | number | 山河图坐标(0-100)，从 world-map.js 迁入 | 17, 33 |

**死字段处理（M0决策）**：`event_weight`（无读取者）→ 删除或接线；`visual_keywords`/`background_asset_key`（未消费但 design/9.2 Q版美术将用）→ 保留待美术。

### 3.3 山河图重构（world-map.js）

- playable 节点（9图）位置/可达性 **从 map_table 读取**（wx/wy/node_kind + getAvailableMaps），废 WORLD_MAP_NODES 里重复的 wild/chentang/kulou 硬编码。
- flavor 节点（cave洞府/朝歌/玉虚宫/金鳌岛/封神台地标）保留为叙事地标，`reach:()=>false` 直到未来内容开放（不阻塞）。
- 推进链可视化：点亮"下一站推荐"节点 + 路径 lit（合 F3 显式链）。
- 平行"地图列表"（ui.js renderMapPanel 卡片墙）**降级为节点详情**：点山河图节点 → 展开该图详情（探索点/遭遇/Boss群/驻留）。

### 3.4 gate 逻辑（unlock-manager.js getAvailableMaps）

```
unlocked(map) = realm ≥ map.unlock_realm            // 主锁（已有）
             && (map.prev_map == null               // 前置链（F3弱锁）
                 || unlocked(map.prev_map))
```
弱锁说明：因境界已隐式排序，prev_map 极少实际阻拦；其价值在**显式路径**与未来同境界多图排序。卡玩家风险低（见§九）。

## 四、② 单地图层设计（空间纵深）

### 4.1 每张图 = 探索点群 + 遭遇池 + Boss群

```
驻留地图(current_map_id)
   → 游历行动（action_table 该图行）结算
        → map_explores[map_id]++
        → 触发探索点发现（discover_after 门槛，6.5）
             → 发现点可 trigger_event（6.6事件）/ unlock_encounter（6.6遭遇）
        → 遭遇池抽取（_setupActionExtras，按 map_id + requires_point 过滤）
   → Boss群（按 boss_table.map_id 聚合，见§五）
```

### 4.2 补齐后6图（缺口1+3）

**游历行动**（action_table 新增6行，去 ui-constants.js:133 `MAP_ACTION` 硬编码改读表）：

| action_id | map_id | 名称 | 文案方向 |
|---|---|---|---|
| xiqi_patrol | map_004 | 西岐巡阵 | 西线战场，阐殷对峙 |
| shijue_probe | map_005 | 十绝探阵 | 杀阵十门，逐阵试探 |
| huanghe_cross | map_006 | 黄河渡劫 | 九曲黄河，削境之水 |
| wanxian_watch | map_007 | 万仙观阵 | 万仙来朝，截教钟声 |
| fengshen_gaze | map_008 | 封神台瞻榜 | 金榜在上，榜文压制 |
| hunyuan_contemplate | map_009 | 混元悟道 | 自辟天地，超脱大劫 |

> ui.js 改：游历按钮从 `MAP_ACTION[current_map_id]` 改为 `action_table.find(a=>a.map_id===current_map_id)`；ui-constants.js:133 `MAP_ACTION` 删除（或保留为fallback）。

**探索点**（explore_point_table 新增 ~30点，map_004~009 各5，对齐 design/6.5 每图≥4）：
- 字段沿用：point_id/map_id/name/flavor/discover_after/reward/secret，部分深层点带 trigger_event + unlock_encounter（对齐6.6）。
- discover_after 递增（1/3/6/10/15），早期易得、深处深耕。
- 叙事咬合（6.6）：西岐→战场遗迹/十绝→阵眼残骸/黄河→河眼/万仙→仙踪/封神台→榜文碎片/混元→道韵。
- 复用 `map_explores[map_id]`（已有）+ `explored_points`（createDefault+normalize 兼容旧档，6.5已建）。

### 4.3 驻留语义增强（缺口6）

`current_map_id`（驻留）统一驱动：① 离线收益（reward-manager.js:30，已有）② **在线游历行动**（该图的 action_table 行）。驻留从此有在线意义——换图 = 换游历产出/遭遇/Boss群。
