## 二、目标与原则

### 2.1 北极星
玩家能在手机浏览器里**完整、流畅、有内容纵深**地体验"修行→择法→破劫→站队→上榜"的核心循环，前 30 分钟有钩子，前 7 天有目标，之后有赛季盼头。

### 2.2 五条原则
1. **先单机跑通乐趣，再联网放大乐趣**——任何联网系统都必须先有单机可验证的核心循环。
2. **内容是当前第一瓶颈**——G1/G2 优先于 G5/G6。系统已够，先把已有系统填满。
3. **H5 体验是"手游"的入场券**——G3 与内容并行，否则内容再好也像网页 demo。
4. **数据表驱动 + 服务端权威从第一天设计**——客户端只表现，结算逻辑预留服务端迁移。
5. **每阶段单独验收 ≥ 85 分才进下一阶段**（沿用 `design/3.0` §8 门槛）。

### 2.3 平台路线
- **现在 → P2**：纯 Web H5（竖屏），GitHub Pages 部署，快速迭代。
- **P3 起**：H5 套 App 壳（iOS/Android，WebView 或 Capacitor），同时上服务端。
- **渲染**：保持 DOM/CSS（文字修仙品类适配），不急于上 Godot；若后期特效需求重，再评估 Canvas/WebGL 局部渲染。

### P1 — H5 手游体验（与 P0 并行）

> 目标：消除 G3。让它在手机上"像个手游"而非"网页 demo"。

1. **触摸与手势**
   - 所有按钮加 `:active` 触感反馈 + 最小点击区 44×44px。
   - 弹窗/抽屉支持下滑关闭、边缘返回。
   - 战斗速度键、配招拖拽（可选）手势化。
2. **新手引导重做**
   - 前 3 分钟强制引导：吐纳→首灵光→首战→配招→破劫，每步聚光 + 一句封神锚点。
   - 复用战斗 V2 三层教学，扩展到全局。
3. **性能与加载**
   - 首屏 JS 分包/懒加载（战斗引擎进战斗时再载）。
   - 图片懒加载 + WebP + 占位骨架。
   - 长列表（机缘 98/遭遇 66）虚拟滚动或分页。
   - 目标：中端机首屏 < 2s，战斗帧率稳定。
4. **PWA / 离线**
   - `manifest.json` + Service Worker 缓存静态资源，可"加到主屏幕"。
   - 离线收益与 SW 缓存解耦（离线收益是游戏机制，SW 是资源缓存）。
5. **机型适配**
   - 竖屏锁定 + 安全区（刘海/底部 home 条）适配。
   - 主流分辨率（375/390/414/360）布局回归。
6. **设置与体验**
   - 速度偏好持久化、字号调节、震动反馈（可选）。
- **验收**：手机浏览器实测流畅；新玩家无说明 3 分钟内完成首战；PWA 可安装离线打开。
- **工作量**：约 2–3 周。

### P3 — 服务端权威 + 云存档（消除 G5）

> 目标：联网地基。所有产出/战斗/概率/时间由服务端结算。

1. **技术选型**：Node.js/TypeScript 模块化单体 + PostgreSQL + Redis（依 `design/3.0` §3.2）。
2. **账号系统**：手机号/第三方登录，设备绑定。
3. **云存档**：存档即云存档，本地仅断线缓存；多端同档。
4. **服务端结算**：行动产出、战斗回合、破劫概率、掉落全部服务端权威；客户端只上报操作 + 表现。
5. **时间权威**：按服务端时间算离线/挂机收益，改本地时间无效。
6. **防作弊 + 审计**：操作日志可回放，异常账号可审计。
7. **数据表校验**：JSON 数据表服务端校验，客户端渲染。
- **验收**：改本地时间无效；双端同账号同档；操作可回放。
- **工作量**：3–4 周。

### P4 — 社交 + 赛季（消除 G6）

## 五、内容生产管线（支撑 P0/P2 的批量内容）

> 内容空洞是反复出现的瓶颈，必须建立管线而非每次手搓。

1. **数据表模板化**：每类内容（术法/Boss/遭遇/机缘/同伴）定 JSON Schema + 校验脚本，填表即校验。
2. **封神锚点强制字段**：每条内容必填 `lore_anchor`（一句封神出处），保证世界观一致。
3. **AI 辅助 + 人工校审**：用子代理批量生成候选文案/数值，人工按 `design/5.1` 评分标准校审入库。
