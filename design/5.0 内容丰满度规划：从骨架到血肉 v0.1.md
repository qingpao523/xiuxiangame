# 5.0 内容丰满度规划：从骨架到血肉 v0.1

> 生成于 2026-08-16。触发原因：当前版本系统框架已跑通，但内容极度稀疏——3 门术法、3 个 Boss、3 位 NPC、3 张地图、20 个事件——玩家 30 分钟后即触底，"不像游戏"。本文档是内容生产的总纲，逐系统给出从当前到卷七的完整内容清单、数据表结构与优先级排期。

## 二、术法/神通体系（5 系 × 5 阶 = 25 门）

### 2.1 设计原则

- 真仙前称"术法"，真仙后称"神通"——同一门法术随境界进阶改名、改特效、改数值。
- 5 系对应 5 种战斗风格，玩家不必全学，但每系至少有一张牌进入牌库。
- 每系 5 阶：初阶（炼气士）→ 中阶（真人）→ 高阶（地仙/天仙）→ 神通（真仙）→ 大道神通（金仙+）。
- 初阶免费学一门（现有机制），中阶起消耗残页+法力+特定材料。
- 每门术法对应一张战斗卡牌，卡牌数值随术法等级成长。

## 三、NPC/封神人物因缘（3 → 20 位）

### 3.1 设计原则

- 每位人物有 3-5 个阶段（登场→事件→结缘→深化→终局），不是一次性对话。
- 结缘后给：专属战斗卡牌 + 永久被动 + 洞府立绘。
- 人物按境界/势力/地图分布，玩家不可能一周内全部遇见。
- 每个人物必须挂接一个封神锚点（榜文/劫气/功德/阐截/杀劫/神位）。

## 十二、内容质量标准

### 12.1 每条内容必须满足

1. **封神锚点**：每条术法/Boss/NPC/法宝/事件必须挂接至少一个封神原著元素。
2. **即时可用**：玩家获得时立即有用，不存在"需要 X 系统解锁后才能用"。
3. **选择感**：至少 50% 的事件/机缘有 2 个以上选择，且选择有实际后果。
4. **文案质量**：每条叙事文案≥3 句，有场景、有动作、有封神味；禁止"你获得了 X"式干巴文案。
5. **数值锚定**：所有奖励/伤害/消耗必须锚定当前境界的 base_daoxing_per_min 和 combat_power_base，不允许出现"前期神器后期垃圾"或"后期数值溢出"。

### 12.2 验收检查清单

- [ ] 新档 30 分钟内能遇到≥3 种不同遭遇
- [ ] 新档 30 分钟内能学到≥2 门术法（含免费 1 门）
- [ ] 第 1 天结束时牌库≥10 种牌
- [ ] 第 2 天结束时已遇见≥2 位 NPC
- [ ] 第 3 天结束时已挑战≥3 个不同 Boss
- [ ] 第 7 天结束时仍有未解锁内容可见（雾中地图/灰锁术法/未登场 NPC）
- [ ] 任何时刻玩家能说出"我下一步可以做什么"且答案≥3 个

## 十四、总结

当前游戏的问题不是"系统不够"，而是"每个系统里只有 1-3 条内容"。解法：

1. **术法**：3 → 25（5 系 × 5 阶），每系有明确的战斗风格与封神来源。
2. **NPC**：3 → 20，按境界/势力/地图分布，每人 3-5 段故事。
3. **Boss**：3 → 30+，分层（遭遇/地图/破劫/杀阵/榜文残影/心魔）。
4. **地图**：3 → 9，每图 6-10 遭遇 + 1-2 Boss + 专属掉落。
5. **事件**：20 → 100+，按章节分布，50% 有选择。
6. **法宝**：9 → 30+，封神名器残影系列，5-8 级成长。
7. **卡牌**：12 → 35+，牌库构筑深度。
8. **丹药**：3 → 12，法力/材料经济出口。

**核心原则：填数据表，不加系统。先填深度，再扩广度。先战斗，后叙事。先可玩，后美术。**

预计总工作量：~400 行 JSON 数据 + ~200 行卡牌定义 + ~300 段叙事文案。代码改动集中在 CARD_DEFS 扩展与 UI 面板适配，核心引擎不需要重写。
