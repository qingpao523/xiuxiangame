# 8.0 战斗系统整体性改版设计文档 V1

> 生成于 2026-07-01。本文档为战斗系统从"卡牌回合制"到"斗法栏连锁制"的整体性改版设计。
> 前置文档：`design/6.0`（画卷哲学）、`design/6.1`（对标烟雨江湖）。
> 核心判断：当前卡牌制战斗"操作多、决策浅"——每回合点3张牌，但出哪张牌是无后果的假选择。
> 改版方向：**配招5分钟，斗法全自动。爽感来自"我配的招秒了"，策略来自"怎么配更猛"。**

---

## 一、设计理念

### 一句话

配招5分钟，斗法全自动。爽感来自"我配的招秒了"，策略来自"怎么配更猛"。

### 从《烟雨江湖》吸收的核心基因

| 基因 | 含义 | 在本系统中的体现 |
|------|------|-----------------|
| 选择有重量 | 技能稀缺+不可逆的道统分支，让配置决策有"怕选错"的紧张感 | 6格上限+6系=必须取舍；本命流派不可逆 |
| 动脑比无脑强 | 会搭配的人比无脑堆强力单体的人强30-50% | 连锁加成+终极效果 vs 散搭高稀有度 |
| 确定性回报 | 玩家永远知道"我离下一个三连还差什么" | 斗法栏可视化，同系高亮，差一格就三连 |

### 为什么放弃卡牌制

| 当前卡牌制问题 | 改版如何解决 |
|---------------|-------------|
| 每回合抽6张随机牌，出牌顺序无意义 | 固定栏位，顺序由玩家决定，100%确定性 |
| 3AP限制让"出哪张"变成假选择（反正都能出完） | 无AP概念，栏位即全部，配好就完事 |
| 手动/自动切换割裂体验 | 全自动执行，策略深度前置到配招阶段 |
| 19种Boss机制但玩家侧无对应策略维度 | Boss抗性/弱点直接对应系属选择，配招即策略 |
| 牌库膨胀后抽到关键牌靠运气 | 没有牌库，所有技能都在栏里，所见即所得 |

### 保留什么

| 保留项 | 原因 |
|--------|------|
| 本命流派（benming_school） | 构筑身份核心，与六系天然契合 |
| Boss特殊机制（19种） | 内容深度已做好，改为影响配招策略而非出牌操作 |
| 法宝被动效果（RELIC_EFFECTS） | 改为斗法栏外的全局加成 |
| 道友卡 → 道友神通 | 改为神通品类，放入斗法栏 |
| 境界/战力体系 | 决定技能伤害基数，不变 |
| 势力buff/神位加成 | 改为战斗开始时的全局乘区 |

## 二、斗法栏

### 基本规则

| 项目 | 设计 |
|------|------|
| 名称 | 斗法栏 |
| 初始格数 | 3格 |
| 扩展 | 境界突破+1格，最终6格 |
| 放置限制 | 每个技能只能放一格，不可重复 |
| 战斗执行 | 按①→②→③顺序循环释放，全自动，直到一方倒下 |
| 玩家操作 | 仅战前：选择技能、调整顺序 |
| 循环规则 | 一轮=所有格子按序释放一遍；一轮结束后敌方行动；然后下一轮 |

### 格子扩展节奏

| 境界 | 格数 | 解锁时间（预估） | 设计意图 |
|------|------|----------------|---------|
| 练气 | 3格 | 开局 | 教学：只够一个三连或一个二连+散搭 |
| 筑基 | 4格 | ~3天 | 过渡：可以二连+二连，或三连+散搭 |
| 金丹 | 5格 | ~2周 | 策略展开：三连+二连，或双二连+散搭 |
| 元婴 | 6格 | ~1月+ | 完全体：双三连，或三连+二连+散搭 |

### 为什么6格是上限

- 6格 × 6系 = 每系最多1个三连，必须取舍
- 超过6格会让"全三连"变得太容易，策略深度崩塌
- 6格 = 2个三连 或 3个二连 或 1个三连+1个二连+2散搭 → 选择空间恰好

## 三、三种战斗能力

### 分类

| 品类 | 含义 | 获取途径 | 稀有度范围 | UI标识 | 数量预期 |
|------|------|---------|-----------|--------|---------|
| 术法 | 修炼习得的战斗手段 | 修炼/境界奖励/日常积累 | 普通~精良 | 蓝框 | 最多（~30种） |
| 法宝 | 以外物之力克敌 | Boss击杀/秘境探索/机缘事件 | 稀有~传说 | 金框 | 中等（~15种） |
| 神通 | 天赋或极致领悟 | 境界大突破/特殊成就/道统选择 | 史诗~绝世 | 紫框 | 最少（~8种） |

### 设计意图

- **术法**：数量最多，凑系的基础素材。玩家大部分时间在攒术法。每系5-6个，保证前中期同系凑不齐3个
- **法宝**：单体威力高，是"惊喜奖励"——拿到一件好法宝能立刻改变配置格局。但同系法宝稀少，难以凑三连
- **神通**：最稀有，附带特殊效果（非纯数值），是长线追求目标。每个神通都是"build定义者"

### 三者关系

三品类共享斗法栏、遵守同一套连锁规则。区别仅在获取方式、稀有度和UI展示上。**引擎不区分品类，只看系属。**

### 与现有系统的映射

| 现有系统 | 新系统归属 | 迁移方式 |
|---------|-----------|---------|
| spell_table（术法表） | 术法品类 | spell_type直接映射为系属 |
| treasure_table（法宝表） | 法宝品类 | related_spell_type映射为系属；被动效果保留为全局加成 |
| CARD_DEFS中的道友卡 | 神通品类 | 改为独立神通技能，绑定系属 |
| charm_strike/charm_guard | 术法品类（体系） | 改为基础体系术法 |
| talisman_* | 移除 | 画符系统改为战前消耗品buff，不入斗法栏 |

## 四、六系与连锁

### 系属分类

| 系属 | 代码标识 | 封神源流 | 体验定位 | 现有对应 |
|------|---------|---------|---------|---------|
| 体 | body | 肉身修士 | 防御/反击 | charm_guard + 部分法宝被动 |
| 雷 | thunder | 雷部·闻仲 | 爆发/控制 | spell_thunder_01~05 |
| 火 | fire | 火部·罗宣 | 持续伤害 | spell_fire_01~05 |
| 器 | weapon | 器道·太乙/广成子 | 多段/速攻 | spell_weapon_01~05 |
| 魂 | soul | 幽冥·女娲 | 续航/吸血 | spell_soul_01~05 |
| 劫 | calamity | 天劫之力 | 赌命/极限爆发 | spell_calamity_01~05 |

### 连锁规则

| 条件 | 效果 | 演出 |
|------|------|------|
| 相邻两格同系 | 后者伤害×1.3 | 文字变色加粗："——雷系共鸣！" |
| 三格全同系（连续） | 触发该系终极效果 | 全屏遮罩+大字+特殊伤害 |
| 非连续三同系 | 仅触发两个二连（×1.3×1.3） | 两次共鸣文字 |

**关键规则：**
- 跨品类连锁：一个雷系术法+一个雷系法宝=雷系二连 ✅（引擎只认系属）
- 连锁判定在释放时实时计算，不是战斗开始时一次性计算
- 终极效果每场战斗最多触发一次（防止循环刷）

### 六系终极效果

| 系属 | 终极名 | 效果描述 | 演出关键词 |
|------|--------|---------|-----------|
| 体 | 「肉身成圣」 | 本轮无敌+反弹受到伤害的50% | 金光护体，伤害数字反弹 |
| 雷 | 「五雷轰顶」 | 全体麻痹1轮+引爆累计雷伤 | 五道天雷，全屏蓝白 |
| 火 | 「三昧焚天」 | 灼烧DOT伤害翻倍，持续3轮 | 赤火漫天，灼烧数字翻倍 |
| 器 | 「万剑归宗」 | 连续5段攻击，每段独立计算暴击 | 剑雨倾泻，5段数字连跳 |
| 魂 | 「六魂尽灭」 | 本次所有伤害100%转化为生命回复 | 幽绿光芒，血条回升 |
| 劫 | 「万劫不复」 | 牺牲50%当前血量，造成300%攻击力伤害 | 黑红裂变，巨大伤害数字 |

### 连锁与本命流派的联动

| 本命流派 | 连锁加成 | 设计意图 |
|---------|---------|---------|
| 雷修 | 雷系二连加成从×1.3提升至×1.5 | 鼓励雷修凑雷系连锁 |
| 火修 | 火系终极「三昧焚天」持续从3轮→5轮 | 火修终极更强 |
| 器修 | 器系二连额外+10%暴击率 | 器修连锁更爆 |
| 魂修 | 魂系连锁触发时额外回复5%生命 | 魂修连锁续航 |
| 劫修 | 劫系终极反噬从50%降至35% | 劫修终极更安全 |

## 五、策略深度设计

### 为什么不会"无脑三连就行"

| 约束机制 | 效果 | 设计来源 |
|---------|------|---------|
| 技能稀缺 | 前中期同系凑不齐3个，必须用混系二连过渡 | 术法按境界逐步解锁 |
| Boss抗性 | 不同Boss对不同系有抗性/弱点，一套配置无法通吃 | 继承现有19种Boss机制 |
| 格子有限 | 6格上限+6个系=必须取舍，无法每系都凑三连 | 数学约束 |
| 法宝稀缺 | 法宝威力高但同系法宝极少，全放法宝凑不齐同系 | 掉率控制 |
| 神通互斥 | 部分神通有"道统分支"前置，选了A就没了B | 不可逆选择 |

### 策略维度

| 维度 | 决策内容 | 深度来源 |
|------|---------|---------|
| 凑系 vs 强单体 | 三连加成高，但可能放弃一个传说级法宝 | 数值博弈 |
| 对手针对 | 火系Boss→换雷系配置；多Boss轮换→准备多套方案 | 信息博弈 |
| 道统分支 | 境界突破时不可逆选择影响combo参数 | 长线规划 |
| 品类混搭 | 法宝威力高但稀少，全放法宝凑不齐同系；术法多但单体弱 | 资源博弈 |
| 顺序优化 | 同系技能放①②③还是②③④影响连锁触发时机 | 微操空间 |
| 终极时机 | 三连终极在第三格释放时触发，放①②③还是④⑤⑥影响节奏 | 节奏控制 |

### 多套配置方案（后期）

| 解锁条件 | 功能 |
|---------|------|
| 金丹期 | 解锁第2套配置方案（可快速切换） |
| 元婴期 | 解锁第3套配置方案 |
| 化神期 | 解锁第4套配置方案 |

设计意图：Boss战前切换配置方案，类似烟雨江湖的"阵容切换"。

## 六、战斗流程设计

### 完整战斗流程

```
战前阶段（玩家操作）
  ├─ 查看Boss信息（抗性/弱点/机制提示）
  ├─ 选择配置方案（或手动调整斗法栏）
  ├─ 确认出战
  └─ 点击"开始斗法"

战斗阶段（全自动）
  ├─ 开场：检测三连终极（若满足条件，首格释放时触发）
  ├─ 第1轮：按①→②→③...顺序释放
  │   ├─ 每格释放：计算伤害（基础×连锁×抗性×本命×全局buff）
  │   ├─ 连锁判定：与前一格同系→×1.3
  │   └─ 终极判定：连续三格同系→触发终极（每场一次）
  ├─ 敌方回合：Boss执行意图（攻击/蓄力/施法/召唤）
  ├─ 第2轮：循环...
  ├─ ...
  └─ 结束：一方HP归零 或 达到最大轮数

结算阶段
  ├─ 胜利：奖励+演出
  └─ 失败：安慰奖+提示
```

### 与现有Boss机制的适配

| 现有机制 | 新系统适配方式 |
|---------|--------------|
| summon（召唤小妖） | 小妖有独立HP，玩家技能默认打主目标；器系终极「万剑归宗」可溅射 |
| thunder_immune（雷免疫） | 雷系技能伤害=0，战前提示"此敌免疫雷法" |
| fire_immune（火免疫） | 同上 |
| five_rotate（五行轮转） | 每轮切换免疫系，玩家需混系配置应对 |
| block_regen（回罡） | Boss每轮回复护盾，器系「万剑归宗」破盾 |
| realm_cut（削境） | 每轮玩家最大HP递减，鼓励速战（雷/劫爆发） |
| immortal（不死） | 需单轮打出超过Boss最大HP的伤害→终极+连锁爆发 |
| four_swords（四剑轮转） | Boss固定4轮攻击模式，玩家需在间隙爆发 |
| picture_world（画中世界） | 3轮内双方伤害-50%，魂系续航优势 |
| six_soul（清buff） | 清除玩家增益状态，火系DOT不受影响（已施加的燃烧保留） |

## 七、新手教学设计

### 体验弧线（前10分钟）

| 时间 | 事件 | 教会什么 | 封神浓度 |
|------|------|---------|---------|
| 0-30秒 | 首战：打妖猪 | "同系放一起更强" | 零（纯朴素教学） |
| 30秒-3分钟 | 获得第1个雷系术法 | "新技能怎么融入配置" | 开始出现 |
| 3-10分钟 | 获得第2个雷系术法→三连达成 | 全屏「五雷轰顶」的啊哈时刻 | 拉满 |

### 首战教学详细流程

**Step 1：系统默认给3个体系术法**
- 拳法初式（body）
- 蓄力拳（body）
- 气劲击（body）
- 默认排列：①气劲击 ②蓄力拳 ③拳法初式（故意非连续同系——等等，三个都是体系，应该故意打乱让玩家发现同系相邻的概念）

**修正：** 默认给2个体系+1个雷系：
- ①拳法初式（body）
- ②掌心雷（thunder）
- ③蓄力拳（body）

这样①③同系但不相邻，玩家需要发现"把同系放一起"。

**Step 2：自动打一轮→猪没死**（伤害不够，因为没触发连锁）

**Step 3：三层递进引导**
- 第一层（0秒）：两个体系技能格子边框高亮抖动（给聪明人3秒自己发现）
- 第二层（3秒后无操作）：文字提示"同系术法相邻，或有奇效……"
- 第三层（8秒后仍无操作）：箭头直接引导拖拽

**Step 4：玩家调整顺序→体系二连触发→伤害×1.3→猪死了**

**Step 5：结算文字**
> "你悟到：同系道法相邻施展，气机共鸣，威力倍增。此乃——道法共鸣。"

### 第二次教学（雷系三连）

- 3分钟后获得"雷部残卷"→解锁第2个雷系术法
- 此时玩家已有：掌心雷(thunder) + 雷部残卷(thunder) + 拳法初式(body)
- 引导：把两个雷系放一起→二连
- 再获得第3个雷系→三连→「五雷轰顶」全屏演出
- 啊哈时刻："我配出了三连！"

## 八、战斗演出设计

### 界面布局（竖屏文字风格）

```
┌─────────────────────────┐
│  【山野妖猪】 ████████░░ │  ← 敌方血条
│                         │
│  ① 拳法初式 → 82       │  ← 逐行滚动
│  ② 蓄力拳  → 82        │
│  ── 体系共鸣！×1.3 ──  │  ← 这行变色加粗
│  ③ 气劲击  → 107       │
│                         │
│  你 ████████████░░      │  ← 己方血条
│                         │
│ ┌─蓝─┐ ┌─蓝─┐ ┌─蓝─┐  │
│ │拳法 │→│蓄力│→│气劲│  │  ← 当前执行格高亮
│ └───┘ └───┘ └───┘   │
└─────────────────────────┘
```

### 演出层级

| 触发条件 | 演出效果 | 实现方式 |
|---------|---------|---------|
| 普通释放 | 文字行正常滚动 | DOM追加+scrollIntoView |
| 二连触发 | 插入一行变色加粗文字 | CSS class切换 |
| 三连终极 | 全屏黑色遮罩+居中大字+伤害数字掉落 | CSS animation + overlay div |
| Boss机制触发 | 特殊提示行（红色/紫色） | 独立CSS class |
| 暴击 | 伤害数字放大+抖动 | transform: scale + shake |
| 击杀 | 敌方血条碎裂动画 | CSS keyframes |

### 战斗速度控制

| 速度 | 每格释放间隔 | 适用场景 |
|------|------------|---------|
| 1× | 800ms | 首次体验/Boss战 |
| 2× | 400ms | 日常刷怪 |
| 4× | 150ms | 已通关重复挑战 |
| 跳过 | 0ms（直接出结果） | 碾压局 |

## 十、引擎核心逻辑

### battle-engine-v2.js 核心骨架

```javascript
// ===== 战斗引擎 V2：斗法栏连锁制 =====

function runBattle(playerSlots, enemy, options = {}) {
  const player = {
    hp: getPlayerHP(),
    hpMax: getPlayerHP(),
    slots: playerSlots, // [{id, name, spell_type, damage_base, ...}]
    block: 0,
    statuses: { burn: 0, weak: 0, shield: 0 },
  };
  
  const battleLog = [];
  const maxRounds = options.maxRounds || 20;
  let ultimateUsed = false;
  
  // 主循环
  for (let round = 1; round <= maxRounds; round++) {
    // === 玩家回合：按栏位顺序释放 ===
    for (let i = 0; i < player.slots.length; i++) {
      const skill = player.slots[i];
      let dmg = calcDamage(skill, enemy, player);
      
      // 二连判定：与前一格比spell_type
      if (i > 0) {
        const prev = player.slots[i - 1];
        if (prev.spell_type === skill.spell_type) {
          dmg = Math.floor(dmg * 1.3);
          battleLog.push({ type: 'combo', element: skill.spell_type, mult: 1.3 });
        }
      }
      
      // 三连终极判定（每场一次）
      if (!ultimateUsed && i >= 2) {
        const prev1 = player.slots[i - 2];
        const prev2 = player.slots[i - 1];
        if (prev1.spell_type === skill.spell_type && 
            prev2.spell_type === skill.spell_type) {
          const ultResult = applyUltimate(skill.spell_type, player, enemy);
          battleLog.push({ type: 'ultimate', element: skill.spell_type, ...ultResult });
          ultimateUsed = true;
        }
      }
      
      // 应用伤害
      enemy.hp -= dmg;
      battleLog.push({ type: 'attack', skill: skill.name, damage: dmg, element: skill.spell_type });
      
      if (enemy.hp <= 0) {
        return { result: 'win', rounds: round, log: battleLog };
      }
    }
    
    // === 敌方回合 ===
    const enemyDmg = calcEnemyDamage(enemy, player);
    player.hp -= enemyDmg;
    battleLog.push({ type: 'enemy_attack', name: enemy.name, damage: enemyDmg });
    
    if (player.hp <= 0) {
      return { result: 'lose', rounds: round, log: battleLog };
    }
  }
  
  return { result: 'timeout', rounds: maxRounds, log: battleLog };
}

function calcDamage(skill, enemy, player) {
  let dmg = skill.damage_base + skill.damage_growth * (getSkillLevel(skill.id) - 1);
  
  // 抗性/弱点
  if (enemy.resistance[skill.spell_type]) {
    dmg *= (1 - enemy.resistance[skill.spell_type]);
  }
  if (enemy.weakness[skill.spell_type]) {
    dmg *= (1 + enemy.weakness[skill.spell_type]);
  }
  
  // 本命流派加成
  dmg *= getBenmingMultiplier(player.benming_school, skill.spell_type);
  
  // 全局乘区（战力缩放）
  dmg *= getPowerMultiplier(player);
  
  return Math.floor(dmg);
}

function applyUltimate(element, player, enemy) {
  const ult = COMBO_ULTIMATE[element];
  switch (ult.effect_type) {
    case 'invincible_reflect':
      player.statuses.invincible = ult.duration;
      player.statuses.reflect = ult.reflect_rate;
      return { name: ult.name, effect: 'invincible' };
    case 'paralyze_detonate':
      enemy.statuses.paralyze = ult.paralyze_turns;
      const storedDmg = enemy.storedThunderDmg || 0;
      enemy.hp -= storedDmg;
      enemy.storedThunderDmg = 0;
      return { name: ult.name, effect: 'paralyze', bonus_damage: storedDmg };
    case 'dot_multiply':
      enemy.statuses.burnMultiplier = ult.multiplier;
      enemy.statuses.burnMultiplierTurns = ult.duration;
      return { name: ult.name, effect: 'dot_boost' };
    case 'multi_hit':
      let totalDmg = 0;
      for (let h = 0; h < ult.hit_count; h++) {
        const isCrit = Math.random() < 0.3;
        const hitDmg = Math.floor(calcDamage(player.slots[0], enemy, player) * 0.6 * (isCrit ? 2 : 1));
        totalDmg += hitDmg;
        enemy.hp -= hitDmg;
      }
      return { name: ult.name, effect: 'multi_hit', total_damage: totalDmg };
    case 'lifesteal':
      // 本轮所有伤害已造成，回血
      return { name: ult.name, effect: 'lifesteal', rate: ult.steal_rate };
    case 'sacrifice_burst':
      const cost = Math.floor(player.hp * ult.hp_cost);
      player.hp -= cost;
      const burstDmg = Math.floor(player.hpMax * ult.damage_mult);
      enemy.hp -= burstDmg;
      return { name: ult.name, effect: 'sacrifice', cost, damage: burstDmg };
  }
}
```

## 十三、数值框架

### 伤害公式

```
最终伤害 = 基础伤害 × 等级成长 × 连锁乘区 × 抗性乘区 × 本命乘区 × 全局乘区 × 暴击

其中：
- 基础伤害 = damage_base
- 等级成长 = 1 + damage_growth × (level - 1) / damage_base
- 连锁乘区 = 1.0（无连锁）/ 1.3（二连）/ 终极效果（三连）
- 抗性乘区 = (1 - resistance) × (1 + weakness)
- 本命乘区 = 1.0~1.5（取决于流派匹配）
- 全局乘区 = 战力缩放 × 法宝被动 × 势力buff × 神位加成
- 暴击 = 1.0（普通）/ 2.0（暴击，基础5%+器系加成）
```

### 敌方HP缩放

```
敌方HP = 基础HP × 境界系数 × 难度系数

境界系数：练气=1, 筑基=3, 金丹=10, 元婴=30, 化神=100
难度系数：普通=1, 精英=2, Boss=5, 天劫=10
```

### 平衡锚点

| 阶段 | 玩家DPS/轮 | Boss HP | 预期轮数 | 体验 |
|------|-----------|---------|---------|------|
| 练气（3格） | 200-300 | 500-1000 | 3-5轮 | 快速，教学 |
| 筑基（4格） | 500-800 | 2000-4000 | 4-6轮 | 开始有策略 |
| 金丹（5格） | 1500-2500 | 8000-15000 | 5-8轮 | 连锁成型 |
| 元婴（6格） | 5000-8000 | 30000-60000 | 6-10轮 | 完全体 |
