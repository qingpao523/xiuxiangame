# 1.7 Godot Web MVP 技术方案与开发任务拆分 v0.1

## 一、文档目标

本文档用于把《封神修道录》的 MVP 从“玩法规格”推进到“可执行开发方案”。

本阶段目标不是继续扩展世界观，也不是补完整封神榜、神位、真仙神通、大罗混元，而是明确：

用什么技术做
项目怎么组织
数据表怎么落地
存档怎么设计
离线收益怎么结算
页面怎么流转
美术资源先准备哪些
功能怎么拆任务
怎么调试和验收

MVP 目标仍然锁定：

炼气士一重 → 地仙一重

核心玩法仍然是：

闭关收菜
道行升重
封神机缘
术法升级
本命法宝
地图结算
破劫突破
本地存档

---

# 二、技术目标

## 2.1 第一版平台目标

MVP 第一版目标平台：

```text
Web / H5 原型
```

运行方式：

浏览器中运行 Godot Web 导出包。
玩家通过网页打开游戏。
首版不做账号系统。
首版不做服务器。
首版使用本地存档。

优先适配：

PC 浏览器
移动浏览器竖屏

首版重点不是多平台完美兼容，而是最快验证：

收菜循环是否爽
封神机缘是否有期待
法宝是否有战力爆点
前 7 天是否能留住人

---

## 2.2 技术栈选择

推荐技术栈：

```text
Godot 4.x
GDScript
2D / Control UI
本地 JSON 数据表
user:// JSON 存档
Web 单线程导出
```

不建议首版使用：

C#
复杂 3D
多人联网
服务器存档
热更新
复杂粒子
大型 Spine / 骨骼动画
复杂自动战斗系统

---

## 2.3 为什么用 Godot

本项目不是纯网页表格工具，而是一款需要氛围的放置修仙游戏。

Godot 适合本项目的原因：

主界面需要主角立绘。
封神榜背景需要动效。
破劫需要简单动画。
法宝获得需要表现反馈。
机缘弹窗需要仪式感。
后续可能导出桌面或移动端。
Control UI 足够支撑放置游戏界面。

本项目第一版不追求最轻网页包，而是追求：

游戏感
动效
封神氛围
后续可扩展

---

## 2.4 Web 端限制与应对

### 限制一：后台不会持续运行

浏览器标签页不活跃时，游戏逻辑可能暂停。

应对：

所有放置收益都用时间戳结算。

```text
离线收益 = 当前时间 - 上次保存时间
```

禁止依赖后台计时持续累加。

---

### 限制二：本地存档可能被清除

Web 存档依赖浏览器侧存储。
玩家清缓存、隐私模式、禁用存储时可能丢档。

MVP 应对：

进入游戏时检测存档可用性。
设置页提供导出 / 导入存档 JSON。
正式版再考虑账号和云存档。

---

### 限制三：导出包比普通网页大

Godot Web 导出会包含引擎运行所需文件。

MVP 应对：

只做 2D UI。
贴图尺寸保守。
不做重粒子。
不做复杂 3D。
音频数量控制。
优先单线程 Web 导出。

---

### 限制四：移动 H5 性能要保守

应对：

主界面用静态背景 + 少量动效。
破劫动画用简单遮罩、缩放、透明度、粒子少量表现。
法宝特效以 UI 动效为主。
所有列表分页或滚动容器不要一次加载过多节点。

全局入口。

核心方法：

```text

reset_game()
get_player_state()
```

---

# 六、离线收益实现规则

## 6.1 结算入口

触发离线结算的时机：

游戏启动后读取存档成功。
玩家从后台回到前台并点击收菜。
玩家主动点击闭关页“领取”。

---

## 6.2 有效离线时间

```text
raw_minutes = floor((now_unix - last_offline_claim_time) / 60)
effective_minutes = clamp(raw_minutes, 0, offline_limit_minutes)
```

如果检测到系统时间倒退：

```text
effective_minutes = 0
弹出提示：时间异常，本次不结算离线收益
```

---

## 6.3 离线上限

炼气士：

4 小时。

真人：

8 小时。

地仙：

12 小时。

新号前 24 小时：

12 小时。

---

## 6.4 收益倍率

```text
total_multiplier =
1
+ map_bonus
+ root_bonus
+ treasure_bonus
+ calamity_bonus
+ temporary_event_bonus
```

MVP 阶段不要用多重乘法，避免数值失控。

---

## 6.5 道行结算

```text
daoxing_gain =
effective_minutes
× current_realm.base_daoxing_per_min
× total_multiplier
```

---

## 6.6 法力结算

```text
mana_gain =
effective_minutes
× current_realm.base_mana_per_min
× map_multiplier
× treasure_multiplier
```

---

## 6.7 地图掉落

地图掉落按有效离线分钟折算。

MVP 简化：

```text
drop_roll_count = floor(effective_minutes / 10)
```

每 10 分钟进行一次掉落判定。

---

## 6.8 机缘触发

机缘检查：

```text
event_roll_count = floor(effective_minutes / 30)
```

每日首次收菜：

必定触发 1 次普通或精良机缘。

如果当前已有 pending_event_id：

先弹出未处理机缘。
不重复抽取新机缘。

---

## 6.9 结算顺序

固定顺序：

```text
1. 读取存档
2. 获取当前时间
3. 计算有效离线分钟
4. 读取当前境界
5. 读取当前地图
6. 计算总倍率
7. 结算道行
8. 结算法力
9. 结算地图掉落
10. 判断机缘触发
11. 判断可升重状态
12. 写入资源变化
13. 更新 last_offline_claim_time
14. 保存
15. 弹出闭关结算窗口
16. 若有机缘，继续弹出机缘选择窗口
```

---

# 七、结算顺序样例

## 7.1 样例一：新号离线 10 分钟

状态：

```text
境界：炼气士一重
当前地图：无
离线上限：12 小时，新手保护
基础道行：1 / 分钟

```

```text

总倍率 = 1

法力 = 10 × 80 = 800
```

```text

可升重：
炼气士一重 → 炼气士二重
```

## 7.3 样例三：真人十重破地仙劫

状态：

```text
境界：真人十重
道行满足：22000
基础成功率：60%
功德：2000
劫气：1000
法宝：玄黄护符 Lv.3
失败补偿：0
机缘加成：地脉初鸣 +10%
```

计算：

```text
功德加成 = 2000 / 100 × 0.5% = 10%
劫气压力 = 1000 / 100 × 0.3% = 3%
玄黄护符加成 = 8% × Lv.3倍率
假设 Lv.3倍率 = 1.5
法宝加成 = 12%
机缘加成 = 10%

最终成功率 =
60% + 10% - 3% + 12% + 10%
= 89%
```

界面显示：

```text
地仙破劫成功率：89%

基础成功率：60%
功德护持：+10%
本命法宝护身：+12%
地脉初鸣：+10%
榜文牵引：-3%
```

成功结果：

```text
境界：真人十重 → 地仙一重
战力提升
解锁：地脉感应
解锁：法宝祭炼
解锁地图：骷髅山边界
获得称号：榜外散修
```

失败结果：

```text

境界不下降
法宝不损坏
失败次数 +1
下次破劫成功率 +10%
法力 +5%
```

连续失败 2 次后：

```text
第 3 次必定成功
```

## 12.2 封神感完成标准

玩家前 10 分钟看到封神榜或榜文碎光。
第 1 天知道自己是榜外散修。
第 3 天理解功德护真灵、劫气借大劫。
第 5 天感受到封神榜感应。
第 7 天破地仙劫时看到榜文牵引。
地图不是通用地图，而是山野劫气、陈塘关、骷髅山。
法宝不是普通装备，而有封神来源说明。

## 12.3 数据安全标准

资源不能为负。
每日机缘不能超上限。
破劫成功率必须限制在 0% 到 100%。
术法等级不能超过当前境界上限。
未解锁地图不能选择。
未获得法宝不能装备。
离线收益不能超过上限。
时间倒退不能刷资源。
存档损坏时能重建新档。

# 十五、最终定义

1.7 的目标不是继续想大后期，而是让项目可以正式进入原型开发。

MVP 的技术定义是：

```text
Godot 4.x + GDScript + Web/H5 + 本地 JSON 数据表 + user:// 存档
```

MVP 的玩法定义是：

```text
炼气士一重到地仙一重的前 7 天闭关收菜循环
```

MVP 的体验定义是：

```text
玩家上线收菜，获得道行，触发封神机缘，选择功德或劫气，得到本命法宝，破劫突破，最终成为榜外地仙。
```

一句话：

**第一版先用 Godot Web 做出一个能从新号玩到地仙一重的封神放置修仙骨架，验证“闭关收菜 + 封神机缘 + 本命法宝 + 破劫成仙”是否真的爽。**
