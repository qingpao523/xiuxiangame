# 9.2 美术风格统一全局设计 v0.1

> 来源：2026-08-20 核心玩法设计会议决策（见 design/9.1 第五节）——美术全面转向 Q 版，类《大话西游》《梦幻西游》，降低 AI 味、吸引女性用户。
> 原则：**不考虑成本，只考虑用户体验**。全量重做，不做廉价替代；同一屏幕内禁止新旧风格混用。
> 状态：本文件生效后，《美术需求.md》第 0 节旧风格锁作废，所有新生图一律使用本文件的「风格锁 v2」。

---

## 一、为什么要全局设计（第一性原理）

玩家对游戏的第一判断是"这游戏是什么气质"，由视觉在 3 秒内完成，早于任何玩法认知。三个不可回避的事实：

1. **风格锁是根**：现有 99 个资产全部由旧风格锁（水墨重彩、"不要卡通Q版"）生成。不改锁，每张新图都继续产出旧气质，局部修补只会制造风格精神分裂。
2. **混用比全旧更糟**：半屏水墨半屏 Q 版，玩家感知到的不是"在升级"而是"廉价拼凑"。因此迁移必须以**屏幕为原子单位**——一个屏幕要换就整套换。
3. **Q 版不等于降精度**：大话/梦幻的神韵来自比例与色彩（20 年前成立），但当年的贴图精度、光影、布料细节放到今天是短板。我们要的是**古典神韵 × 现代精度**，不是复刻怀旧。

## 二、风格定位：古典 Q 版神韵 × 现代手游精度

### 2.1 继承大话/梦幻的（神韵层）
- **人物比例**：3~4 头身，圆润轮廓，大头大眼，五官集中偏下；
- **色彩**：明快、温暖、高饱和但不刺眼，主色一眼可辨（仙=青白金、妖=紫绿、劫=暗红紫）；
- **气质**：东方可爱感（萌而不腻），角色有表情戏，装备夸张化、符号化（大拂尘、大葫芦、大铡刀）；
- **场景**：层次分明的卡通透视，远景柔和、近景清晰，地标夸张化（昆仑就是巨大的仙山、朝歌就是巨大的黑红王城）。

### 2.2 超越 20 年前的（精度层）
- **材质细节**：布料有织纹与滚边、金属有拉丝与反光、玉石有通透感——远看是 Q 版，放大看有东西；
- **光影**：柔和全局光 + 明确主光源 + 角色边缘光，立体感靠光影不靠描边堆线；
- **分辨率**：立绘/背景按 2 倍移动屏密度输出，图标至少 256px 画布；
- **无 AI 味红线**：禁止蜡像皮肤感、过度对称构图、无意义细节堆砌、眼神空洞。

### 2.3 保留封神味的（世界观层）
- Q 版≠西化：服饰仍是商周仙侠体系（深衣、道袍、甲胄、法器），不用西式铠甲与翅膀；
- 封神锚点视觉化：榜文=金色卷轴光、劫气=紫色雾、功德=暖金光圈，全游戏统一这三个符号色。

### 2.4 主题锁（用户 2026-08-21 指令）
- **封神风格是主题，Q 版是表达方式**：Q 版解决"气质可爱、降低 AI 味"，封神解决"这是什么游戏"。每张图必须至少含一个可识别封神锚点（商周服饰/法器/榜文/劫气/功德/经典地标或人物典故），纯通用可爱仙侠 = 主题缺失 = 不合格。

## 三、风格锁 v2（替换《美术需求.md》§0，所有新提示词必带）

## 四、资产迁移分波计划（按玩家体验曝光顺序，不按生产成本）

**原子性铁律**：一个屏幕涉及的所有素材必须在同一波内全部换完才允许上线；宁可整屏晚换，不许半屏混用。

### 每波的节奏
波内流程：定调图先行 → 用户确认气质 → 批量生成 → 逐张对照第五节验收 → 整波一次性替换上线。**任何单张 <95 分不入库**。

## 五、验收标准（唯一裁判：design/9.3 v0.2）

验收两道门（用户 2026-08-22 改口径）：**红线一票否决 → 总分 100 且 ≥95 通过**。禁止再用 v0.1「五维每项 ≥95」。金标、扣分、分类专项、清单见 `design/9.3`。

整波体验验收（P0/P1/P2 各一次，在逐张过门后执行）：
1. **真机走查**：390×844 竖屏预览，从进入走到本波覆盖的最深处，记录每一屏；
2. **零混用检查**：任一同屏出现新旧风格并存 → 整波判废打回；
3. **3 秒气质测试**：把本波任 3 张图给未参与设计的人看，能否说出"可爱的中国神话游戏"——说不出即气质不达标；
4. **女性用户视角检查**（本次转风格的明确目标人群）：配色是否有吸引力、角色是否可爱、有无劝退的暗黑元素。

不达标的资产记录缺陷后重生成，**不设"先凑合后替换"通道**。

## 六、代码零改动策略

1. **文件名不变、路径不变**：所有新素材按原文件名原位替换（如 `boss_001_shanye_yaoshou.png` 原地覆盖），JS/CSS 零修改；
2. **格式对齐**：原 jpg 位图位继续用 jpg，透明底素材保持 png；新图输出尺寸不小于原图，避免 UI 缩放模糊；
3. **替换动作集中在每波末尾一次性执行**，配合 devlog 记录；替换后立即跑 `python3 -m http.server 8090` 真机走查第五节验收；
4. **回滚预案**：git 提交按波粒度打 tag（`art-p0` / `art-p1` / `art-p2`），任何波验收翻车可整波回滚，不影响代码。
