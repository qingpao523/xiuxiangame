### 0.3 三个超出思考稿认知的新发现（实读核实）

**A. 概率 roll 根本不参与结算——"显示"与" reality"结构性脱钩。**
breakthrough-manager.js:12-46 的完整 breakdown（剧情+功德+法宝+地脉+失败补偿+跟脚+阵营+道友护持−劫气）只有两个去处：① ui.js:1037-1061 确认面板的"总成功率"表格；② game.js:1114 塞进 payload 后再无人读取。结算唯一依据是斗法胜负（battle.win，battle-engine-v2.js:1688 / :694 / :778）。ui.js:1064 的提示文案承诺"以上因果护持会化为你开局的气机罡气"，但实际只有殷郊结缘 `trib_shield` 一人给了开局罡气（battle-engine-v2.js:194-196）。**即：玩家堆功德、压劫气、叠法宝，面板百分比在涨，实际破劫体验纹丝不动。** 这不是文案问题，是"数值承诺了、玩法不兑现"的出戏结构。

**B. bt 表 phases 是死数据，bt_003~bt_008 六关共用 bt_001 的两段劫。**
constants.js:176 的 `TRIBULATION_PHASES` 只有 bt_001/bt_002 两个键；game.js:1112 `TRIBULATION_PHASES[id] || TRIBULATION_PHASES.bt_001` 兜底——真仙劫到混元劫六关，打的都是"榜文碎光(0.75)→金影照灵(0.95)"。bt_006/007/008 表里写好的"大道试问·精气神心""过去因/现在果/未来劫/三世归一/斩尸""榜文金雷/三尸/天道之手"全部无人消费。**数据为体的架构原则在破劫这里是反着来的：数据源被硬编码常量架空了。**

**C. phases 战斗跑在 D 线模型之外。**
battle-engine-v2.js:88-89 与 :1684：phase 敌 HP = playerPower/playerHpMax × power_ratio，无 diff 钳制、无 ENEMY_TARGET_ROUNDS、无攻击力公式——回合数随境界漂移，正是 devlog D 线记录的病根在破劫路径上的残留。技术债比 devlog 写的更深一层：不只是"未纳入模型"，还有"数据双源 + 六关同模"。

## 1. 石海的标准

| # | 石海观点（2026-08 科隆访谈） | 对破劫体制的要求 |
|---|---|---|
| ② | "不能出戏"是前提 | 破劫面板承诺的因果护持必须真实兑现（0.3-A）；六关同一张脸必须消除（0.3-B）。**出戏是破劫当前最大的病。** |
| ④ | 从文化作品本身思考创作 | 思考稿 §1 已从原著推出五条文本依据（劫是定数/应在入世/上榜非好事/根行定路径/替身合法）。标准要求的是把这些推导落到每一次破劫交互里，而不是停在文档。 |
| ③ | 回到原点思考品类本质，拒绝缝合 | 放置品类的本质是"确定性成长 + 长时间尺度的节奏节点"；破劫是节奏的标点。拒绝把破劫做成通用修仙的"掷骰子+扣血"缝合件——思考稿 §2 的"劫是世界的定数，破劫是名位深浅"正是回到原点的结论。 |
| ① | 好游戏=反复玩 300-500 小时 | 破劫要供给长线内容：list_marks 收集、敕封分支、杀劫压力随赛季涨落，都是"毕业之后还来"的钩子（与 21.3 终局轨交汇）。 |
| ⑤ | 疲劳点是最大陷阱 | 六关同模的劫战（0.3-B）是结构性疲劳点：玩家从真仙到混元要打六次同一个 Boss 皮。phases 入模 + 每关独有判词，是把疲劳点改造成节奏点的最小代价。 |
| ⑫ | 结构高于实现 | 思考稿的三层结构（世界层杀劫压力/数值层名位/玩法层三条破劫路）是对的；落地顺序必须先定结构再动实现，且每一步改动都服务于结构，不做孤立功能。 |
| ⑨ | 80 分不能发，要 92-95 分 | **纯换皮是 80 分动作**：文案承诺了"名位/榜文留名"，机制不兑现，换皮越彻底出戏越深（见 2.1）。所以零代码起步必须与"显示=现实"修复绑定交付，单独换皮不发。 |

## 2. 差距分析（现状 vs 标准）

### 2.1 出戏清单（按严重度排序）

1. **因果不兑现**（0.3-A）：玩家按 ui.js:1041-1048 的明细表去经营功德/劫气/法宝，结果只改变一个显示数字。石海标准②的硬伤——玩家一旦发现"护持是假的"，破劫从"参与封神"退化为"看脸打 Boss"。
2. **六关同模**（0.3-B）：真仙→混元六次破劫共用 bt_001 两段 phases。标准⑤的结构性疲劳点，也是标准④的直接违背——原著里每一劫的"相"是不同的（杀劫/大道试问/因果反噬/榜文全力压制，pressure_label 自己都写了），战斗却长一个样。
3. **失败没有世界观后果**：破劫失败弹窗（game.js:643-645）只有数值补偿。原著语义里"没过劫=真灵被榜文照见"，当前失败与 Boss 斗法失败在体验上无差别——而 Boss 败尚有真灵上榜（:692），破劫败反而没有，世界观倒挂。
4. **保底空头支票**：guarantee_after_fail 传了 payload 无人消费（0.2 表），连败玩家得到的"屡败之后劫火淬体"承诺（ui.js:1064）里，保底那一半不存在。
5. **劫是按钮不是世界**：破劫随点随开，无榜文牵引的时机感、无杀劫压力的涨落——思考稿 §2① 的"世界层"完全空白（array 杀阵是唯一沾边的容器）。

### 2.2 结构性缺口

- **三条破劫路只有"战"一条**：代形替身无道具载体（但 pill_table 模板现成）、功德抵名无消费出口（merit 只加面板百分比）。
- **list_marks / 敕封分支**：代码 grep `list_marks` 零命中（21.3 §0.2-A 同结论）；但 god_seats 已证明"失败=收集"在本作可行且有世界观先例——**缺口不是从 0 到 1，是把 Boss 败的既有链路接到破劫败上并升格**。
- **phases 数据双源**：bt 表与 constants 各一套（0.3-B），违反"数据为体"（design/14.0 §K A1），后续任何破劫改动都会撞上这堵墙。

## 3. 改善提案

### 3.a 五个待拍板决策的推荐（立场：不出戏、从原著来、改动最小）

| # | 决策 | 推荐 | 理由 |
|---|---|---|---|
| 1 | 劫的层级：A 全局杀劫压力 / B 个人事件只换皮 | **选 A，但第一步按 B 走**（目标 A、起步 B） | 原著里劫是世界的定数（思考稿 §1.1），只做 B 等于把封神体制阉割成个人考试，违背"不出戏"；但 A 的世界事件内容量大，一次做完违反"改动最小"。故：起步只把 `pressure_label` 语义统一 + 文案换皮（零代码），全局 `calamity_pressure` 状态值放系统级（3.c-3）。A/B 不是二选一，是时序。 |
| 2 | 失败后果：A list_marks→敕封分支 / B 维持劫火淬体 | **选 A，B 保留为数值底座** | ① god_seats 已验证"失败=收集"玩家接受度（game.js:873 链路已在三个败局场景跑了很久）；② A 不拿掉 B：fail_bonus/mana 补偿原样保留，list_marks 纯增量；③ 放置底线"失败也必须给成长"（见 §4）要求 list_marks **只给正反馈**（天庭差事/保底加速），不做"缕数越多劫越强"的负惩罚——这是对思考稿 §2④ 的唯一修正。 |
| 3 | 替身代形：A 消耗品系统 / B 不做 | **选 A，极简单行版** | 替身是原著母题（思考稿 §1.5），且是破劫前唯一能新增的"主动选择点"，直接服务 CLAUDE.md 守则 2"参与封神"。但不建通用消耗品系统：照 pill_table 模板加一行"替身符"，结算处加一个消耗判定即可（3.c-2.4）。B 的代价是三条破劫路永远缺一条，结构残缺。 |
| 4 | 敕封神道线：A 隐藏结局 / B 正式第二境界线 / C 不做 | **选 A** | B 工程量是重做一条 realm 线（realm_table/combat/文案全套），违反改动最小且与 21.3 终局轨重复建设；A 有现成挂点：hy_10 lore 已问三条路、`ending_choice` 死指针待接（21.3 §0.2-A）、list_marks 阈值可做隐藏选项解锁条件。C 不做则决策 2 的 list_marks 积累没有终点，长线钩子烂尾。敕封结局=原著"上榜亦是果位"的完整表达，但做成**玩家可选**（见 §4 取舍）。 |
| 5 | 破劫 phases 入难度模型 | **做，且前置为一切低代码改动的先决任务** | 纯技术债（devlog D 线遗留），且实读发现债比记录更深（0.3-B/C：死数据+六关同模+模型外）。任何 list_marks/替身符/语义化改动都要碰破劫结算与战斗创建路径，不先还债就是在双源数据上叠新债（石海⑫：结构先于实现）。具体方案见 3.c。 |

### 3.c 破劫 phases 纳入难度模型的还债建议（决策 5 展开）

**根因**（第一性拆解）：
1. 数据双源——bt 表 phases（死）与 constants TRIBULATION_PHASES（活）并存，违反 A1"数据绝对中心"；
2. 模型缺席——phase 敌 HP=playerPower×power_ratio 是 D 线之前的旧公式，无 diff 钳制、无回合数目标带、无攻击力公式（battle-engine-v2.js:88-89/:1684）；
3. 内容塌缩——bt_003~008 无 phases 数据 → 兜底 bt_001 → 六关同模。

**还债四步**（即第二档 1.1，此处给验收口径）：
1. 数据归一：bt 表为唯一 phases 源，constants 硬编码删除（保留意图池 `TRIBULATION_INTENT_POOLS`，它本来就是按关设计的，constants.js:170-174）；
2. 模型接入：phase 敌完全复用 D 线公式，`power_ratio` 语义重定义为"该 phase 的 diff 权重"（bt_001 两段 0.75/0.95 换算后手感须与黄金快照一致）；
3. 内容补齐：bt_001~005 补 phases（每关 2-4 段，名称/intro 从各关 lore 推导，不新造世界观）；
4. 度量回归：balance-metrics 增加"8 关×全 phase"采样点，目标带（3-8 回合/phase）命中 ≥ 8/11 同 D 线验收口径；**bt_001 单独加"前 30 分钟手感冻结"断言**（回合数、吃血比例与快照逐帧一致）。

## 4. 风险与取舍（逐条对照 CLAUDE.md 守则）

| 守则 | 对照结论 |
|---|---|
| 1 好玩优先 | ✅ 每一步都回答"给玩家什么选择/风险/世界信息"：1.2 让经营因果真实生效（选择有效）、1.6 替身符给破劫前决策点、1.5 天庭差事给世界信息。纯换皮（0.1-0.3）本身不产生选择，故只作为搭车交付，不单独立项。 |
| 2 参与封神 | ✅ 破劫斗法本就操作密集；本提案补的是"战前参与"（替身符/功德抵名）与"战后后果"（留名/差事），把破劫从结算点拉回事件链。 |
| 3 前 30 分钟最高优先级 | ⚠️ **最大风险点**：bt_001 是第一场破劫，落在 1.9 规格的 30 分钟闭幕链路附近（真人劫第 1 天）。对策：1.1 还债给 bt_001 上黄金快照锁，零代码档 bt_001 文案只润色不改信息量；任何 phase 数据重标必须过"前 30 分钟快照零漂移"断言后才许合入。bt_001 的 min_success_rate 0.95 软保底语义保留。 |
| 4 弹窗克制 | ✅ 全程零新增模态：list_marks +1 走浮字/日志（仿 game.js:879 日志句式），天庭差事走既有 event 弹窗队列（一次一个），敕封选项并入 hy_10 既有结局弹窗。 |
| 5 不强制养成路线 | ✅ 三条破劫路（战/替身/功德）并列可选；敕封是隐藏结局非必经；替身符可完全不碰。**对思考稿 §2④ 的修正**："缕数越多后续劫越强"改为"缕数越多保底越快+差事越多"——放置品类失败不得产生净负反馈，否则违反本条守则精神。 |
| 6 世界观是玩法的一部分 | ✅ 全系统挂锚点：榜文（phases/留名）、杀劫（压力值/杀阵）、功德（抵名）、神位（敕封）、阐截（劫气/阵营护持）。无一个裸数值系统。 |
| 7 手游网游长期 | ✅ list_marks/calamity_pressure 均为纯 state 标量，服务端权威友好（20.0 已完成服务端执行架构）；神位收集天然适配排行榜稀缺位（授满 6/6 的账号展示）。 |
| 8 先读文档再动手 | ✅ 本稿依据 devlog D 线、1.8/1.9（前 30 分钟）、2.0、2.2、21.3（终局）实读产出；实施任务开工前须复查 devlog 最新条目。 |

**底线命题专项论证："失败也必须给成长" vs "失败是另一条路"**

两者是递进而非对立：
- **底线层（不可让步）**：任何失败不得净减玩家资产。现有 fail_bonus/mana 补偿、god_seats 授位全部保留；list_marks 只加不减、只给正反馈（差事、保底加速、敕封资格）。替身符"败转胜但不授 title"是唯一带代价项，且代价=放弃本可选择的正常胜利奖励，属于玩家主动决策的后果，不是失败的惩罚。
- **升格层（本提案的核心主张）**：原著里"该上榜的终究上榜"是定数强制，游戏里把它翻转为**玩家主权**——留名积累到阈值时，系统问一句"天庭敕令已至，受封还是拒命"。失败积累的不是惩罚进度条，而是另一条路的入场券。这才是石海④"从文化作品本身思考"的落点：封神体制的精髓不是"渡劫成功学"，而是"定数之下，人如何自处"。
- **护栏**：敕封弹窗必须可拒绝且拒绝后不再重复弹窗（每 N 天才重申一次，走 event 频控），防止"失败=被系统催着换路线"的压迫感——那会同时违反守则 4 与 5。
