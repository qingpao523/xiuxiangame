## 1. 石海的标准

引用 21.0 所列访谈观点（编号沿用）：

- **① 好游戏 = 他想玩 300-500 小时、大家反复吃的东西；90% 玩家只玩 20-30 小时的产品不是好产品。**
  → 翻译成本作标准：终局不是"通关字幕"，是"反复吃的理由"。混元不是终点，是"开始反复吃"的起点。若玩家到混元后没有"明天还想打开"的理由，那么 90% 玩家的实际寿命会在楼梯的某一环断掉——而楼梯有 90 环。
- **⑤ 疲劳点是最大陷阱。** 天国拯救复盘原话："驱动我的是装备 → 装备没法更好了 → 捡到的都是破烂 → 我只是把它从郊外搬进城卖掉 → 我又在爬楼梯了。你的疲劳点在哪，是很大的问题。"
  → 这段话是一个**链条**：追求毕业 → 掉落贬值 → 行为降级为搬运 → 行为失去意义只剩爬升。诊断必须逐环做，不能只回答"疲劳点在第几层"。
- **⑨ 痛恨重复性内容和"为折磨人而折磨人"。**
  → 两条禁令：其一，终局内容不得是同一条楼梯的换皮续段；其二，失败惩罚若是纯痛苦（扣资源、掉进度）而无叙事意义，就是折磨。本作破劫失败补偿"劫火淬体"与真灵上榜"败亦化神位"方向正确，应推广。
- **⑫ 结构高于实现。**
  → 终局问题必须在结构层回答（"什么不毕业"），而不是在实现层打补丁（再加 30 层塔、再开 10 重境界）。

**结论**：本作的疲劳点不是一个点，是**楼梯本身**。石海问"你的疲劳点在哪"，本作的诚实回答是：从内容毕业点（金仙/太乙）到混元的每一级都是疲劳点，混元之后的每一天都是"搬破烂"。

### 2.2 三段式疲劳断裂（诊断）

1. **第一断裂（现状，20-30 小时处）**：天仙·初期叙事断供（CAP_NOTICE_TEXT）。内容停供后玩家进入纯数值走廊——这正是石海口中"90% 玩家流失"的位置。
2. **第二断裂（卷四~八补齐后仍会发生）**：具名 Boss 内容是有限的（31 个，D2 锁定纯 1v1 具名）。补完八卷后，太乙/大罗玩家打完最后一个有名有姓的对手，战斗退化为数值验证的重复——石海 ⑨ 的重复性内容。
3. **第三断裂（终局）**：混元 = 绝对真空。三结局 0 实现、赛季 0 实现、转世是"重爬楼梯"。毕业后每日上线没有任何"想知道接下来发生什么"的理由。

### 2.3 核心命题：数值必毕业，什么不毕业？

三个候选方向的评估与挂接点（全部基于现有架构实测）：

**方向 A · 叙事/身份层——"我在封神大劫中的名位与因果"（推荐主轴）**

封神神学依据已在 design/破劫设计思考 §1 考证完毕：劫是世界的定数；"根行深者肉身成圣，根行浅者榜上封神"；上榜亦是果位。**玩家在大劫中的"名位深浅、因果厚薄"是原著本来的追求**，且它天然没有数值天花板——名位不是标量，是档案。

现有挂接点（全部是活钩子）：
- `god_seats`（game.js:5-18）：六部神位已是"名位"的微型实现，扩为 365 正神位框架（单机先做"历世神位"，网游期全服争夺，接 design/3.0 §3.3）。
- `list_marks`（破劫思考 §2④）：破劫失败/斗法败北累计真灵留名缕数 → 敕封分支。挂载点就是现有 god_seats 发放处，一行累计。
- `merit/calamity` + breakthrough_table 的 `merit_bonus_cap/calamity_penalty_cap`：功德/劫气已是名位的货币，只差"被世界看见"的表达层。
- `state.rebirth.log`（"第 X 世：XX，修至 XX，凝道痕 X"）：历世档案结构已在——名位天然是跨世的，转世不清档案，只添新篇。
- design/20.0 服务端 + 排行榜已上线：名位/因果是唯一天然适合"被其他玩家看见"的终局资产。

**方向 B · 世界层——杀劫纪元（赛季演化）**

design/3.0 §3.3 已有框架："赛季「大劫」：3 个月一季，每季一个劫运主题（封神劫 → 巫妖劫 → 西游劫）；赛季末按功德/杀劫战绩发放 365 正神位"。挂接点：world-scroll.js / atmosphere.js / scroll-scene.js 的征兆/天象层（世界呼吸已存在），杀劫压力值可升格自 breakthrough_table 的 `pressure_label`（破劫思考 §2①）。**注意：方向 B 是 A/C 的时间轴滚动器，不是独立追求——没有身份与见证作内容，赛季就是换皮楼梯（详见 4.2）。**

**方向 C · 收集/见证层——阅尽封神众生**

封神 IP 最强资产是 365+ 具名人物群像（design/9.0 五维盘点已入库）。玩家作为大劫"史官/见证者"：收集众生结局——谁死了、谁上榜了、谁与我结了因果。挂接点：companion_table stages（19 人因缘已实现）、boss_table 首杀、event_table `lore_anchor` 强制管线（design/10.0 §9 已在跑）——**每卷见证是纯文案内容，生产方式与现有 AI 批量+人工校审管线完全一致，边际成本低**。形态建议："封神榜·见闻录"——每有具名人物上榜/成圣/堕劫，若玩家与其有因果，解锁一卷见证文案。这是每日 2-5 分钟"领奖"的最佳替换物：领的不是资源，是信息（详见 3.1）。

**取舍结论：A 为骨、C 为肉、B 为息。**
- A 是唯一同时满足三条的追求：封神神学原生（CLAUDE.md 守则 6）、现有代码有活钩子、单机→网游无缝（20.0 已就绪）。
- C 是 A 的日常形态，把"2-5 分钟领奖"接在叙事欲望上。
- B 是 A+C 的赛季化节奏，严格后置（先单机闭环，后开赛季——合 design/3.0 §2.3 与石海"先做单机"）。

## 3. 改善提案

### 3.1 设计立场（先于三档方案）

**立场一：数值楼梯在金仙让位，不在混元。**

- 神学依据：封神原著中，金仙是"仙籍"的分水岭——金仙之前是"修自己"（闭关涨道行），金仙开始被卷入大劫因果（三花聚顶、斩三尸、万仙阵）。design/1.3 自己的叙事也写：金仙解锁封神台挑战、太乙进入万仙阵战场、真仙破劫选流派（D3 已锁，身份抉择其实已在真仙发生）。
- 内容依据：具名 Boss 供给上限就在金仙~太乙段（0.2 节）。指望 90 级每级有实内容是幻想；石海 ⑨ 禁止用重复内容续楼梯。
- 结构动作（系统级，见 3.4）：
  - 炼气→真仙：数值楼梯为主（快、密、爽，前 30 分钟守则不动）；
  - 金仙破劫起：数值梯度刻意放缓（现有指数曲线本就陡峭，顺势即可），**身份/因果/见证成为主追求**，境界面板从"下一个数字"变为"我的名位档案"；
  - 太乙→大罗：数值退为"入场券"（参与大劫事件的资格），不再是目的；
  - 准圣→混元：**不应再是楼梯**。建议压缩——准圣/混元的"重"不再有数值成长，改为因果/名位条件 + 终局抉择。hy_10 那个 8.26e13 的死字段就是"楼梯续到天涯"的病证。

**立场二："每日 2-5 分钟"与石海"流连忘返"不调和数值，只调和对象。**

- 放置品类放弃的应是"数值肝的流连忘返"——那恰是疲劳点本身；保留并提供的是"2-5 分钟仪式的流连忘返"：每日开卷 = 封神见闻录更新（谁死了、谁上榜了、我的因果熟了没）、杀劫天象变了没。**石海的 300-500 小时来自"总想知道接下来发生什么"，不是"总想看数字变成多少"。**
- 形态：每日 2-5 分钟领"劫报"（叙事信息，非阻断浮字/日志，合守则 4）；有空时的长会话留给可选项（镇魔塔、因果事件、大劫事件）。
- 红线：**禁止"不上线就落后"的数值 FOMO**——那是"为折磨人而折磨人"（石海 ⑨），也违反 CLAUDE.md 守则 5（不强制养成路线）。赛季/杀劫事件一律"错过可补叙"，不设数值惩罚。

## 4. 风险与取舍

### 4.1 CLAUDE.md 八条产品守则逐条对照

| # | 守则 | 结论 |
|---|---|---|
| 1 | 好玩优先于功能堆叠 | ✅ 本轨核心是"更换追求对象"而非堆新系统；见闻录每卷先回答"带来什么世界信息"（一个具名人物的命运），回答不了不写 |
| 2 | 参与封神而非点点点 | ✅ 结局抉择、名位积累、见证皆有后果；"领奖"从领资源改为领劫报，仪式感保留、点击器属性不变 |
| 3 | 前 30 分钟最高优先 | ✅ 本轨零触碰开局；显式声明：终局设计不得反向挤压前期节奏（金仙让位 ≠ 金仙前减速） |
| 4 | 弹窗克制 | ✅ 结局画卷为一世一次的大弹窗；日常见证一律非阻断浮字/日志 |
| 5 | 不强制养成路线 | ⚠️ 唯一需警惕处：名位条件不得成为破劫/结局的**唯一**门槛。取舍：结局达成条件设计为"功德/杀劫/见证多维可替代"，三条结局对应三种玩法偏好（放置党→受封、战力党→成圣、长线党→逍遥，与 1.3 §24 原设一致），任何一条都不是必走路径 |
| 6 | 世界观是玩法的一部分 | ✅ 全部挂钩封神锚点：榜文/杀劫/功德/名位/敕封/因果，无一处原创架空系统 |
| 7 | 手游/网游/长期运营 | ✅ 身份层天然跨设备、可赛季化；20.0 服务端已就绪；单机只是过渡形态的原则在此轨得到执行 |
| 8 | 先读文档再动手 | ✅ 本文为纯思考稿，未动代码数据；实现前按守则先读 devlog/1.8/2.0/2.2 |

### 4.2 赛季制与石海观点的冲突检查（三条硬约束）

石海反感的是**网游商业绑架**（留存 KPI/付费驱动内容），特意先做单机；本作 20.0 已网游化、3.0/10.0 规划赛季。冲突不在"网游"这个形态，而在赛季内容**会不会变成换皮楼梯**。判别标准只有一句话：玩家回来是因为"想玩"，还是因为"不敢不玩"。据此立三条硬约束，未来赛季版本逐条审计：

1. **赛季不抬数值天花板**：境界锁死 100 节点、法宝基础数值不膨胀。赛季内容 = 劫事件/榜单/局势/见闻（信息型与身份型），谁在版本清单里写"新增境界/装备数值 +X%"，谁就是换皮楼梯，一票否决（可做审计脚本检查项）。
2. **赛季结算不清零身份资产**：延续 design/3.0 §7.4"转世保留道痕、图鉴、外观、称号"——赛季重置的是"本次劫的因果进度"，不是玩家的名位档案。石海恨的是"我又在爬楼梯"；赛季若重置楼梯，就是网游版的天国拯救悲剧。
3. **商业化只卖便利与外观**：禁售境界/神位/成功率（design/10.0 §11 已明文，design/3.0 §6 同），保持。

另立**次序约束**：赛季必须等单机终局闭环（E2/E3/E4/S1）验收后才开闸——否则赛季没有身份内容可滚，必然沦为"换皮楼梯凑赛季"。这与石海"先做单机"和 CLAUDE.md 守则 7 并不矛盾：守则 7 要求的是**按服务端/赛季预留结构**，不是提前开赛季。

### 4.3 其他风险

| # | 风险 | 对策 |
|---|---|---|
| R1 | 身份层变成"新 KPI"（玩家被迫追名位数值） | 名位必须是多维档案（路径/因果/见证），不做单一可比标量；不设名位排行榜的数值压力位（荣誉展示可以，进度逼迫不行） |
| R2 | 见证文案产能不足 | 复用 10.0 §9 lore_anchor 管线 + 9.0 资料库，AI 批量 + 人工校审；首批只做 19 同伴 + 31 Boss 的关键节点 |
| R3 | 三结局选择焦虑/一选定终身 | 结局是"身份结算"不是"删档"：后结局世界开放，转世可达另一结局（转世机制已存在，E3 修复后代价合理） |
| R4 | 与镇魔塔既有定位冲突 | 12.0 §0.3 定义塔为"进度支柱/留存钩子"（纯数值语义）。本轨不废除塔，但主张天仙段以后塔层主题化为"历劫见证"（Z3 已铺）：同一座塔，前 50 层是楼梯，后 50 层是众生相——塔从"数值支柱"转为"数值+见证双支柱"。此为与 12.0 的显式分歧点，提请设计主控裁决 |
| R5 | 金仙让位被误读为"金仙后没事干" | 让位 ≠ 空窗：金仙后空出的数值时间，正是给名位/因果/见证的产能让路；若 S1/S2 内容未就绪而先行放缓数值，会制造真空——因此 3.5 次序中"金仙梯度放缓"必须以 E4/S1 上线为前提 |

## 5. 验收钩子（未来实现时的可核对标准）

1. **三结局**：调试通道直达 hy_10 → 出现三选一抉择 → 选择后 `state.ending_id ∈ {fengshen, chengsheng, xiaoyao}` → 终局画卷文案展示 → 后结局状态下世界仍开放、转世后可达另一结局。审计项：unlock_table 存在 3 行 ending_*；grep `ending_choice` 有消费代码（死指针消除）。
2. **list_marks**：单元测试——破劫失败/斗法败北各使 `state.list_marks +1`；达到阈值 N（待定）触发敕封/差事事件（event_table 行存在且可触发）；audit_integrity 通过。
3. **道痕修复**：`getRebirthPreview` 对 10 个大境的 gain 全部 >0 且单调（测试覆盖全部 major_realm）；新结算表写入数值文档并经设计师校准签字。
4. **见闻录**：具名 Boss 首杀 / 同伴弧关键节点 / 破劫成败 → witnessed +1 且浮字提示；同一条目二次不触发（seen 去重测试）；洞府见闻录面板可展示全部已收集条目，条目均带 lore_anchor。
5. **零代码文案**：breakthrough_table 8 关文案 grep 检查——不再出现裸"成功率 %"式数值表述（改为名位叙事）；tower_table 100 层 lore_anchor 无重复、全部可在 9.0 资料库溯源。
6. **疲劳点运营指标（上线后钩子）**：定义"毕业后日均动作构成"埋点口径——若混元玩家日均动作中"领离线 + 登塔"占比 >60% 且无叙事动作，判身份层未生效（此即石海"搬破烂"的可测代理指标）。
7. **赛季红线（未来版本审计）**：任一赛季版本的内容清单中若出现"数值天花板提升"条目，按 4.2 约束 1 一票否决；赛季重置逻辑测试——道痕/图鉴/名位档案跨赛季保留。
