# 22.0 分批实施验收总标准 v0.1

> 立项背景：design/21.0~21.6 石海标准改善提案六轨已验收通过（均 ≥95），进入**实施期**。本文件是 21.x 思考稿落地为代码/数据时的**统一实施验收标准**，先于一切实施任务产出。
> 适用对象：第 1/2/3 批全部实施任务（executor 实施 + verifier 独立验收）。
> 与 21.0 的区别：21.0 验收的是"思考稿质量"；本文件验收的是"实现质量"。
> 上位依据：CLAUDE.md 核心规范 #6（验收先行）、#7（禁止简化）、#8（验收对齐完整范围）。

## 一、实施流程（每个任务强制五步）

```
① 验收标准先行   主理人从该轨 §5 验收钩子 + 本文件 §二 通用维度，实例化出本任务验收单（满分100）
② executor 实施  P7 实施 agent 按设计完整范围实现，禁简化；产出改动 + 自测证据
③ verifier 验收  独立验收 agent 逐项核对验收钩子、跑验证命令、打分；与 executor 分离，不放水
④ 裁决          ≥95 通过；<95 打回 executor 返工，循环至达标
⑤ 记 devlog      通过后由主理人追加 devlog：日期/变更/关键决策/验收分
```

**角色铁律**：
- executor 与 verifier **必须是不同 agent**，verifier 不得复用 executor 的自评结论。
- verifier 只认**可复跑的证据**（命令输出/测试结果/grep/快照 diff），不认"我已经做完了"式陈述。
- 任何任务开工前，其验收单必须先存在并随任务 brief 一并下发。

## 二、通用评分维度（满分 100，≥95 通过）

| # | 维度 | 权重 | 5 分（满）标准 | 1 分标准 |
|---|------|------|---------------|---------|
| 1 | **范围完整性** | 30 | 对照该轨 §5 验收钩子**逐项**实现，无一项遗漏或降级；设计写"系统"就做成系统 | 简化成按钮+buff、漏项、自降为"最小版" |
| 2 | **功能正确性** | 25 | 行为与设计一致；相关测试/断言/harness 全绿；边界与失败路径正确 | 主路径勉强通、边界崩、测试红 |
| 3 | **架构合规** | 15 | 守"数据为体、画面为用"：逻辑不绑渲染、文案进 JSON 显示字段、逻辑键用 ID 不用中文、state 标量可序列化 | 逻辑写死在视图层、中文当逻辑键、新增渲染耦合 |
| 4 | **回归与护栏** | 15 | 前 30 分钟黄金快照零漂移；`npm test` 六套全绿；不新增开局弹窗负担；触碰项的既有断言（如 companion-passives 20 条）原样通过 | 快照漂移、任一测试红、开局新增模态 |
| 5 | **可验收证据** | 15 | 证据可复跑：验证命令+输出、快照对比、grep 命中清单；对抗审查留痕；devlog 已含验收分 | 只有口头陈述、证据无法复现 |

## 三、硬性否决项（触发任一即判 <95，直接打回）

1. **简化/降级实现**：把设计要求的系统做成简化版、能力代替系统、按钮+buff 交差（违 CLAUDE.md #7）。
2. **黄金快照漂移 / 前 30 分钟回归**：`test/ui-regression` 黄金快照变化，或开局新增阻断模态、新增长干等。
3. **任一测试套件红**：`npm test` 六套（battle/game/chain/ui/css/server）或任务指定的专项测试（companion-passives / balance-metrics / boss-mechanics / opening-walkthrough）任一失败。
4. **审计不过**：`node audit_integrity.js` 或 `node audit_completeness.js` 报错。**⚠️ 基线现状（2026-08-31 实测）**：这两个脚本在 8.3 战斗引擎废除（commit 41a5fe7，`battle-engine.js`→`battle-engine-v2.js`）后未同步更新，读取已删除文件而在基线即崩溃，且其 playCard/CARD_DEFS 检查语义对 v2 引擎已失效。**在审计专项修复完成前，本条暂不作為硬否决门**；硬门以 `npm test` 六套 + 黄金快照零漂移 + 任务指定专项测试为准。审计修复另立待办，修复后本条恢复生效。
5. **无 devlog / devlog 无验收分**：通过后未追加 devlog，或 devlog 未记验收得分。
6. **越权改动**：改动了任务 brief 授权范围外的文件且未显式声明理由。
7. **验收自评放水**：验收钩子未逐项核对即给高分；verifier 复用 executor 自评。

## 四、统一验证命令（verifier 必跑，证据入验收单）

```bash
# 语法
for f in web/js/*.js; do node --check "$f"; done
# 数据审计（⚠️基线损坏：8.3 引擎废除后未更新，读取已删除的 battle-engine.js 即崩溃；修复前不作硬门，见否决项#4）
node audit_integrity.js && node audit_completeness.js
# 全量回归（六套）
npm test
# 前 30 分钟黄金快照（UI 回归，含开局口径）
node test/ui-regression.test.js
# 专项（按任务涉及选跑）
node tests/companion-passives.test.js     # 道友护持基线 20 断言
node test/balance-metrics.js              # 数值目标带采样
node tests/boss-mechanics.test.js         # Boss 机制 50 断言
node tests/opening-walkthrough.cjs        # 开局走查
```

**黄金快照处置**：任务**不得**以 `--write` 覆盖快照来"通过"回归；确因设计内改动需更新快照，必须在验收单中显式列出 diff 并说明其为设计预期，经主理人确认后方可 `node test/ui-regression.test.js --write`。

## 七、内容文案红线（涉及文案的任务适用，源自 21.2/21.5）

- ≤25 字/句；禁系统腔/感叹号结算腔；气韵句内禁裸 `+N`；须含六锚点之一（榜文/劫气/功德/阐截/杀劫/神位）或具体世界实体。
- **禁系统语言入玩家文案**：不得出现"好感+1""立场值-5""成功率+%""目标达成："等面板腔。
- 禁止变形三条（21.5）：榜文≠任务板/排行榜；破劫≠雷劈特效；功德≠可购买通货。
- 放置契约数字白名单（21.2 A 类）：离线收益/破劫 rate-table/HP/伤害浮字/进度条的数字本体不得被气韵化删除，只允许加气韵引言。
