# 23.3 移动端 HUD 重做设计 v0.1（从素材出发，根治 CSS 切片病）

> 2026-09-03 · 用户拍板（原话）：「根本原因是因为你拿一套新的东西，按原来的框架去 CSS 裁剪，把它贴进去，这样的逻辑是不对的……要从根本上解决 CSS 裁剪的问题，你重新去做这一套，不要偷懒，不要只是把图切进去。另外只考虑移动端，不用考虑 PC 端」

## 一、病根诊断
之前三轮（移植段 L4385-5585 / 120对齐覆盖 L5262 / 装配修整段 L5587-5731）都是**在旧框架盒子上叠覆盖层**：
- 盒子比例由旧骨架决定（如 #resource-strip 旧高 56px），素材被 border-image 强行切片塞入 → 比例错配、装饰被拉伸变形；
- 同一素材 2-4 处互相打架（ui_title_plaque@4393/5132；ui_resbar_plaque@4574/5160/5268；ui_goal_card@4423/5178/5338；ui_main_btn_ready@4454/4634/5203/5411）；
- 三层覆盖层层打补丁，越补越脏 → 评审「牛头不对马嘴」。

## 二、方法论（本次重做的铁律）
1. **盒子尺寸由素材天然比例反推**：每区先定宽，高=宽÷素材宽高比，用定宽定高/aspect-ratio 锁死，绝不把图塞进一个比例不对的旧盒子。
2. **整图素材 = `background-size:100% 100%`**（盒比例==图比例→零拉伸变形）；只有「框」类素材（面板卷轴）用正规九宫格 border-image（保角拉边，这是 border-image 的正确用途，不是偷懒切片）。
3. **文字落在素材预留空地**：匾额题字居中、玉璧数值居中、按钮题字居中、导航字上图标下名。
4. **单一权威样式表** `web/style-hud-v3.css`，加载在 style.css 之后，是主屏皮肤唯一真相；**删除** style.css 里 L4385-5731 两段补丁。
5. **只做移动端**（414×896 设计靶），无桌面断点；桌面打开即居中一条手机宽列，不做特殊排版。
6. 色板锁 v3：月白 #fffdf6 / 暖纸 #f7edd4 / 墨青题字 #2e5d6b(深 #1e4450) / 墨绿正文 #33332e / 石青 #3d7a8c / 石绿 #4a8c6a；**金只属天命**（破劫按钮、功德/劫气钮保留 base 金）。
