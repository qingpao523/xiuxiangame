# 8.4 战斗展示层重做与会话隔离 验收标准 v0.1

> 生成于 2026-08-22。承接 `design/8.0`（斗法栏连锁制，规则核不改）与用户当场判定：
> 「整体的战斗在页面呈现上很有问题。战斗完一次之后，第二次把上一次的战斗信息带出来，整体就很混乱。把整个战斗板块、全部战斗引擎都重做一下。技能的排布太 low。整个页面太垃圾。」
> 系统内 `atb_preview.html` 与 `?debug=1` 是调试器；玩家对局不得再长得像调试器。

规则核（连锁 ×1.3、三连终极、条件触发、Boss 机制、夹招）**不改数值、不改 8.0 文法**。重做的是：会话引擎、演出引擎、配招阵面、页面呈现。

---

## 一、本批次范围（对照完整功能点，逐项可核对）

### A. 会话隔离（二次开战不得带上场）
- A1 每场 `create()` 生成唯一 `sessionId`；`abort(battle)` 置 `aborted` 并停播放。
- A2 开新场必须先 `abort` 上一场：清定时器、停异步循环、拆掉整棵斗法 DOM。
- A3 结算钮挂在斗法场内部，禁止再挂到 `#popup-panel`（旧 `.battle-end-row` 残留根因）。
- A4 `showPopup` / `closePopup` 必须清掉 `#popup-panel` 上 title/body/buttons 之外的所有子节点，并复位 class。
- A5 连开两场：第二场标题、血条、战报、结算钮不得含第一场敌名/伤害/按钮。
- A6 旧循环在 abort 后不得再改 DOM、不得再调 `finishBattle`。

### B. 斗法场（玩家看到的是战场，不是调试器）
- B1 战斗走全屏 `#duel-layer`，不再塞进 80vh 弹窗。
- B2 场上有：敌名+血条、己方血条、回合、斗法栏珠、当前出手高亮、敌意图预告、飘字、简短战报。
- B3 默认不展示双轨时间轴调试器（你/敌节点条）。`?debug=1` 才可打开调试覆盖。
- B4 1× / 2× / 4× / 跳过仍在；跳过给出结算摘要。
- B5 胜负后只出现一个主按钮（收取战果 / 退出战圈）；点后才结算并允许下一场。
- B6 立绘：玩家按境界，Boss 按 `BOSS_ICONS`；无立绘用名牌，不留裂图。
- B7 背景按来源（游历山野 / Boss / 破劫封神台），封神锚点可见。

### C. 配招阵面（技能排布不再是 64px+9px 下拉）
- C1 配招走全屏 `#formation-layer`，格宽 ≥ 96px，触控 ≥ 44px。
- C2 每格：序号、术名、系徽、条件芯片（点开选项板，禁止格内原生小 select）。
- C3 点空格再点术法放入；两点交换；✕ 移除；同系相邻高亮；连锁预览仍在。
- C4 条件 6 类文法、法宝绑定、教学三层引导全部保留。
- C5 术法面板「配置斗法栏」仍进入新阵面。

### D. 引擎与调试
- D1 `BattleEngineV2` 步进接口保留；abort 后所有步进返回 `[]`。
- D2 `?debug=1` 调试条增加「试斗一场」，可连点验证 A5。
- D3 `source:"debug"` 的试斗不走遭遇/Boss 结算，只出调试收束。
- D4 开局 5 步 walkthrough 仍过；教学→首战链路不断。

## 四、好看且好玩补强（同日续）

用户当场判定：上一版隔离过了，但「整体太拉、在拖累游戏」。补的是观感与参与，不是再加面板。

| 要点 | 验收 |
|---|---|
| 对手是物不是字 | 山野/调试战用妖首立绘；无图用剪影；名牌在脚下 |
| 出手看得懂 | 栏位亮起全名；符印飞向敌人；飘字；一句台词（体 炼体拳） |
| 可参与 | 亮起时可点「催」，伤害 ×1.15；不点自动放，不卡死 |
| 胜负是戏 | 胜：告捷书法；败：暂退+小记。胜场不得出现「败因」 |
| 不点卡 | 仍是斗法栏自动循环，催动是可选一拍 |

Playwright：敌方有形象、出手台词含术名、连斗不串场、开局 5 步仍过。
