## 〇、定位与决策依据

### 0.1 是什么
镇魔塔是一个**贯穿全生命周期的周期性推塔活动**——玩家每 2 天获得一次登塔机会，从第 1 层逐层挑战具名 Boss，层数越高奖励越丰，挑战随境界缩放，是玩家长期挂在心上的"进度支柱"。

### 0.2 不是什么（边界，避免与既有系统混淆）
- **不是叙事主线**：叙事主脊柱仍是卷章（卷一~卷八，design/4.0/5.0/15.0）。镇魔塔是**玩法支柱**，与主线卷章 / 境界突破 / 流派养成**并列**，不承担剧情推进。
- **不是开放刷怪**：合 D2（纯1v1具名Boss、废推图刷小怪）。塔内每层是**有边界的具名 Boss 挑战**，不是无限刷怪点。
- **不是地图**：不进 map_table / 大地图（design/15.0）。塔是独立活动入口，复用战斗引擎而非地图容器。

### 0.3 为什么（设计意图）
- **留存钩子**：2 天周期 + 逐层进度，给玩家"两天后回来打一塔"的稳定回访理由（对标普通手游的周期爬塔/秘境）。
- **生命链常驻支柱**：随境界缩放，从炼气到混元始终有塔可爬，填充长线空窗（design/10.0 G8 终局空 的早期缓解）。
- **商业化预留口子**：登塔令（券）机制现在设计好接口，券来源（买/赚）留到后期商业化（design/10.0 §11 远期）；当前阶段券可掉落/领取，供无付费测试。

## 一、核心循环

```
周期到（每2天重置）→ 获得 1 次免费登塔 + N 张登塔令（掉落/领取）
  → 进入镇魔塔 → 从「本期起始层」逐层挑战具名Boss（1v1，合D2）
  → 胜 → 结算本层奖励 → 升一层 → 继续（直到败 / 主动止塔 / 用尽时间）
  → 败 → 本期登顶记录定格 → 弹「本期战报」→ 退出
  登塔令：消耗1张可在本期额外开一次登塔（从起始层重爬，奖励独立结算）
周期结束 → 记录本期最高层 → 重置进度 → 新一期
```

- **单次登塔内**：连续爬层，层间不退出（一塔到底），败则止。每层是一场独立 V2 战斗。
- **周期间**：进度（爬到第几层）随周期重置；累计成就（历史最高层、总击杀）永久保留。
- **登塔令（券）**：本期未用完的令不跨期累积（防囤积），下期重置为基础上限。

## 二、周期与券机制

### 2.1 2天周期（mirror 现有 daily reset）
现有日重置：`unlock-manager.js:123 _resetDailyIfNeeded(state)`，键 `state.last_daily_reset_day === todayString()`，清空 `*_counts_today`（event/action/boss/array）。

镇魔塔周期复用同一触发点，新增 `_resetTowerCycleIfNeeded(state)`：
- **周期键**：`cycleIndex = Math.floor(epochDay / 2)`，其中 `epochDay = Math.floor(Date.now() / 86400000)`。每 2 个自然日一个周期。
- **判定**：`if (state.tower_cycle_index === cycleIndex) return;` 否则推进周期、重置进度。
- **调用位置**：挂在 `_resetDailyIfNeeded` 之后（同一 `refresh` 入口，unlock-manager.js:5），保证每次状态刷新都检查。

### 2.2 登塔令（券）—— 商业化口子
- **存储**：`state.tower_tickets`（整数计数器，**非** resource_id；8 个合法资源 daoxing/mana/merit/calamity/spell_page/artifact_shard/treasure_shard/refine_material 不含票，避免污染经济表）。
- **每期上限**：`TOWER_TICKET_CAP = 3`（基线，🔴待校准）。周期重置时 `state.tower_tickets = TOWER_TICKET_CAP`。
- **消耗**：每次登塔（含免费首次）消耗 1 令；令=0 时不可登塔，提示「登塔令已尽，静候下期 / 后期可购置」。
- **当前获取**（无付费测试）：周期重置发放上限张 + 高塔里程碑掉落 + 机缘/活动领取。
- **后期商业化口子**（远期，design/10.0§11）：`purchaseTowerTickets(n)` 接口预留，券来源[买]接入支付；本期不实现，仅留函数桩与字段。
- **防囤积**：令不跨期累积，重置即覆盖为上限。

### 2.3 次数语义（与 Boss 日限区分）
- Boss 日限：`boss_counts_today[bossId] < BOSS_DAILY_LIMIT(3)`（boss-manager.js:18），按**单个 Boss** 计。
- 塔次数：按**登塔令**计（每期上限张），与 Boss 日限**独立**。塔内打到某 Boss **不消耗**该 Boss 的 `boss_counts_today`（塔是独立活动，不挤占地图 Boss 挑战额度）。

## 三、数据模型

### 3.1 state 新增字段（save-manager.js 默认值 + 加载归一化）
```js
state.tower = {
  cycle_index: 0,        // 当前周期号（epochDay/2）
  tickets: 3,            // 本期剩余登塔令
  current_floor: 0,      // 本期当前层（0=未登塔）
  best_floor_this_cycle: 0, // 本期最高层
  in_run: false,         // 是否在一次登塔进行中
};
state.tower_best_floor_ever = 0;   // 历史最高层（永久成就）
state.tower_total_kills = 0;       // 累计塔击杀（永久成就）
state.tower_floor_clears = {};     // { floor: 累计通关次数 }（永久，用于成就/统计）
```
save-manager.js：默认值块（~L38-70）加 `tower:{...}, tower_best_floor_ever:0, tower_total_kills:0, tower_floor_clears:{}`；加载归一化块（~L100-184）加 `state.tower = state.tower || {cycle_index:0,tickets:TOWER_TICKET_CAP,current_floor:0,best_floor_this_cycle:0,in_run:false}; ...`。

### 3.2 新表 tower_table.json（层配置）
顶层结构同其它表：`{schema_version, table:"tower_table", generated_at, description, rows:[...]}`。
每层一行：
```json
{
  "floor": 1,
  "tier": "炼气",
  "boss_id": "boss_001",
  "power_mult": 1.0,
  "reward": { "daoxing": 30, "mana": 800, "refine_material": 1 },
  "milestone_reward": null,
  "lore_anchor": "封神·山野妖患",
  "entry_text": "塔门开启，第一层的妖气凝作一道身影。"
}
```
字段说明：
- `floor`：层号（1 起，连续）。
- `tier`：所属境界段标签（炼气/真人/地仙/天仙/真仙/金仙/太乙/大罗/准圣/混元），用于 UI 分组与缩放（§四）。
- `boss_id`：引用 boss_table 一行（**复用既有 31 Boss**，含九 Boss boss_023-031；魔家四将 boss_026-029 的 `chain_id` 连战在塔内作为"连战层"，§五）。
- `power_mult`：层内 Boss 战力倍率（在 boss.recommended_power 基础上缩放，制造同 Boss 不同层的难度梯度）。
- `reward`：本层通关奖励（合法资源 id；随层递增，§六）。
- `milestone_reward`：里程碑层（每段末层）额外奖励（如 treasure_shard / artifact_shard / 登塔令），普通层为 null。
- `lore_anchor`：封神锚点（**强制**，design/10.0§9 生产管线）。
- `entry_text`：进层半文言演出文案。

### 3.3 不新增的字段（复用）
- Boss 的 `mechanics`/`weakness`/`visual_keywords`/`victory_text` 全部复用 boss_table，塔不重复定义。
- 战斗 cfg 复用 `startBossBattleV2` 的构造逻辑（§七.2）。

## 四、境界缩放（生命链贯穿）

塔层按境界段（tier）分组，玩家**可爬的最高层随境界解锁**：
- **门槛**：`floor_unlock_realm` —— 每段首层挂一个境界门（复用 `UnlockManager.conditionMet(state, realm)`）。炼气段（层1-10）rq_03 开；真人段（11-20）zr_03；地仙段（21-30）dx_01；……混元段（91-100）zs_01。与 map_table.unlock_realm 同节奏（design/15.0 九图境界门）。
- **难度缩放**：同段内 `power_mult` 从 1.0 线性爬到 ~1.5；跨段时 Boss 基础战力随 boss_table.recommended_power 跃升（炼气600→真人8000→地仙45万→金仙8M→太乙100M，沿用 boss_table 既有曲线）。
- **奖励缩放**：reward 数值随段按 boss_table.reward 量级递增（§六）。
- **效果**：炼气玩家爬 1-10 层，混元玩家爬 91-100 层，**同一座塔贯穿全程**，每段都有新 Boss 新奖励——"生命链常驻支柱"。

层布局基线（🔴待校准，首批可先铺 3 段 30 层）：
| 段 | 层范围 | 首层境界门 | Boss 来源 | 段末里程碑 |
|---|---|---|---|---|
| 炼气 | 1-10 | rq_03 | boss_001/023张桂芳/024敖丙/025石矶 等 | 层10 法宝碎片 |
| 真人 | 11-20 | zr_03 | 魔家四将连战(boss_026-029)/030火灵/031罗宣 | 层20 法器碎片 |
| 地仙 | 21-30 | dx_01 | boss_003石矶娘娘/赵公明系 | 层30 登塔令+法宝碎片 |
| 天仙~混元 | 31-100 | tx_01…zs_01 | 既有高阶 Boss 复用+扩 | 每段末里程碑 |

## 五、Boss 投放（复用 boss_table，合 D2）

- **普通层**：1 个具名 Boss（1v1，合 D2 纯具名）。`cfg.enemy_power = boss.recommended_power × power_mult`。
- **连战层**（魔家四将 boss_026-029，`chain_id:"mo_family"` `chain_order:1-4`）：作为塔内一个"连战段"，按 chain_order 顺序连续 4 场（design/8.1 连战机制），全胜算过层。
- **机制**：Boss 的 `mechanics`（如 boss_023 `zhangguifang_interrupt`）原样带入塔战斗——**前提是九 Boss 机制已接线**（design/8.1/8.2，批次0 前置；未接线时塔内 Boss 退化为无机制纯数值战，不阻塞塔本身落地）。
- **弱点**：`boss.weakness` 原样生效，鼓励玩家按层配招（呼应条件触发系统 design/8.3）。
- **不消耗 Boss 日限**：塔内击杀不计 `boss_counts_today`（§2.3）。

## 六、奖励与经济

- **每层 reward**：daoxing + mana + (refine_material|treasure_shard|artifact_shard 之一)，数值随层/段递增，量级对齐 boss_table.reward（如炼气层 daoxing 30-80，真人层 200-500）。
- **里程碑 reward**（段末层）：额外 treasure_shard / artifact_shard / 登塔令 +1，给爬段动力。
- **结算复用**：`_applyResourceDelta(reward)`；可选挂 omen/race/godSeat 战利倍率（与 boss 分支一致，§七.3），但**不挂** first_clear_event / rest popup（塔是连续爬层，不打断）。
- **败不扣**：失败不扣资源，本期登顶定格，给安慰 mana（同 boss 分支 10% 逻辑）。
- **经济定位**：塔是**中量稳定产出**（介于离线挂机与 Boss 首通之间），不破坏 boss 首通的高价值（design/10.0§8 双循环经济）。🔴数值待 design/数值规划与平衡待办 校准。

## 七、代码触点（实现批次用）

### 7.1 周期重置（unlock-manager.js）
`_resetDailyIfNeeded`（L123）后新增 `_resetTowerCycleIfNeeded(state)`：算 cycleIndex，若 `state.tower.cycle_index !== cycleIndex` 则 `state.tower = {cycle_index, tickets:TOWER_TICKET_CAP, current_floor:0, best_floor_this_cycle:0, in_run:false}`。在 `refresh`（L5 区域）调用。

### 7.2 登塔入口（game.js，新增方法）
```js
startTowerRun() {
  UnlockManager._resetTowerCycleIfNeeded(this.state);
  if (this.state.tower.tickets <= 0) { /* 弹「登塔令已尽」text popup */ return; }
  this.state.tower.tickets -= 1;
  this.state.tower.in_run = true;
  this.state.tower.current_floor = 0;
  this._nextTowerFloor();
}
_nextTowerFloor() {
  const floor = this.state.tower.current_floor + 1;
  const row = DataManager.getRows("tower_table").find(r => int(r.floor) === floor);
  if (!row || !UnlockManager.conditionMet(this.state, floorUnlockRealm(row))) { this._endTowerRun(false); return; }
  const boss = DataManager.getById("boss_table", row.boss_id);
  const cfg = { name: boss.boss_name, enemy_power: num(boss.recommended_power)*num(row.power_mult,1),
    adds: [], source: "tower", mechanic: boss.mechanics?String(boss.mechanics).split(":")[0].trim():null,
    weakness: boss.weakness || null, payload: { floor, bossId: row.boss_id } };
  this.startBattleV2(cfg);
}
```
（连战层：若 boss.chain_id，按 chain_order 序列构造多场，复用 design/8.1 连战 auto-advance。）

### 7.3 finishBattle 新增 tower 分支（game.js finishBattle）
```js
if (battle.source === "tower") {
  const floor = int(battle.payload.floor);
  if (battle.win) {
    const row = DataManager.getRows("tower_table").find(r => int(r.floor) === floor);
    const rewards = { ...(row.reward||{}), ...(row.milestone_reward||{}) };
    // 可选：omen/race/godSeat 战利倍率（同 boss 分支）
    this._applyResourceDelta(rewards);
    this.state.tower.current_floor = floor;
    this.state.tower.best_floor_this_cycle = Math.max(this.state.tower.best_floor_this_cycle, floor);
    this.state.tower_best_floor_ever = Math.max(this.state.tower_best_floor_ever, floor);
    this.state.tower_total_kills += 1;
    this.state.tower_floor_clears[floor] = int(this.state.tower_floor_clears[floor]) + 1;
    this._log(`镇魔塔第${floor}层，${boss.boss_name}伏诛。`);
    // 弹本层战报（收取→继续下一层）；不挂 first_clear_event / rest popup
    this._nextTowerFloor();
  } else {
    this._endTowerRun(true); // 败：本期定格，弹战报
  }
  this._afterMutated(); return;
}
```
`_endTowerRun(defeated)`：`state.tower.in_run=false`，弹「本期战报」popup（最高层/累计击杀/奖励汇总）。

### 7.4 UI 入口（ui.js）
- **入口位置**：地图面板（renderMapPanel）顶部加「镇魔塔」卡，或独立 nav 角标（🔴待设计师定，建议先挂地图面板顶部，与「封神山河图」按钮并列）。
- **塔卡内容**：本期剩余登塔令 / 本期最高层 / 历史最高层 / 「登塔」按钮（tickets>0 可点）/ 当前境界段可爬层范围。
- **层进度展示**：登塔中显示「第 N 层 · Boss名」+ 半文言 entry_text。
