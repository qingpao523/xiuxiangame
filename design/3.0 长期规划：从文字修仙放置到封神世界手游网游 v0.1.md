# 3.0 长期规划：从文字修仙放置到封神世界手游网游 v0.1

> 生成于 2026-08-16。本文回答一个问题：当《封神修道录》不再是网页 MVP，而是一款长期运营的移动端网游时，它应该长成什么样。
> 依据：`design/2.0`、`design/2.1`、`design/2.2`、`design/1.8`、`design/1.9`。

---

## 一、产品定位（一句话）

**一款竖屏、长期运营、文字修仙 × 放置 × 赛季制封神大劫的移动网游。**
玩家不是在“挂机升级”，而是在封神前夕的洪荒世界里：修行、站队、渡劫、上榜，最终决定自己要做棋子还是下棋的人。

---

## 二、三条不可动摇的产品支柱

1. **封神世界观不是皮，是机制**：榜文压力、功德/劫气、阐截之争、365 正神位、大劫转世，全部要做成可玩系统，而不是文案。
2. **放置是节奏，不是内容**：挂机负责资源积累；战斗排序、破劫准备、势力选择、大劫赛季负责玩家决策与故事。
3. **先单机跑通乐趣，再联网放大乐趣**：任何社交/排行榜/赛季系统，都必须先有单机可验证的核心循环；但所有代码从第一天起按服务端权威设计。

---

## 三、技术演进路线

### 3.1 当前（MVP 过渡态）

- Web 静态站 + localStorage，纯客户端结算。
- 优点：迭代快，适合验证前 30 分钟与核心循环。
- 边界：不做真钱、不做竞技、不宣称公平；存档明确标注“测试档”。

### 3.2 第一阶段：服务端权威最小闭环

- 客户端：保持 Web/H5 竖屏，后续用 Godot Web 或自研渲染器导出，进 App 壳（iOS/Android）。
- 服务端：Node.js/TypeScript 模块化单体 + PostgreSQL + Redis。
- 核心原则：
  - 所有资源产出、战斗回合、破劫概率、掉落由服务端结算，客户端只做表现与操作上报。
  - 时间收益按服务端时间计算，客户端快进/改时无效。
  - 存档即云存档；本地存档只是断线缓存。
  - 操作日志可回放，异常账号可审计。
- 首个联网版本目标：云存档 + 账号系统 + 防作弊 + 全服排行榜（境界/功德/杀劫战绩）。

### 3.3 第二阶段：社交与赛季

- 势力：阐教/截教/天庭/五庄观，从单机被动改为服务器阵营；势力任务、贡献、地位链。
- 道友：封神人物因缘从单人剧情扩展到 NPC 助战与好友助战。
- 赛季「大劫」：3 个月一个赛季，每赛季一个劫运主题（首赛季封神劫）。
- 封神榜：赛季末按功德/杀劫战绩排名，发放 365 个正神位；正神位是全服可见的稀缺荣誉，可被挑战/继承。
- 轻社交：宗门频道、世界频道、战报分享、观战。

### 3.4 第三阶段：内容与终局

- 金仙仪式线（三花聚顶/五气朝元/斩三尸）。
- 封神战场：阐截站队、杀业/天罚、太乙→大罗→准圣。
- 终局三路线：受封天庭 / 肉身成圣 / 混元逍遥；赛季结束时按路线结算并转世。
- 多赛季内容库：封神劫之后可接巫妖劫、西游劫等，复用“大劫=赛季”框架。

## 四、世界地图的长期定位

封神山河图是**空间轴的外化**，不只是功能入口：

- 前期：一张总图，让玩家知道“榜在头顶，关在海边，山在身后”。
- 中期：地图节点随境界/势力/赛季开放，成为剧情与副本的容器。
- 后期：地图进入“封神战场”状态，节点可争夺、可易主，形成服务器级版图。
- 技术：地图节点数据表驱动；美术图层（底图/地形/路线/迷雾/动态标记）与逻辑层分离，方便替换素材而不改逻辑。

---

## 五、经济与商业化（先定原则，后做系统）

- 双循环经济：道行/法力（修炼循环）+ 功德/劫气（封神抉择循环），新增货币必须回答“它服务哪个世界观决策”。
- 付费定位：月卡/赛季通行证/外观/便利（离线时长上限、一键排序等）为主；首 30 分钟无付费墙。
- 禁止：直接卖境界、直接卖正神位、付费改破劫成功率——这三样会杀死封神题材的稀缺感与赌性。
- 稀缺位商业化：正神位只能赛季玩法产出，但允许外观/称号/洞府皮肤等身份炫耀消费。

## 六、分阶段里程碑

| 阶段 | 内容 | 完成标准 |
|---|---|---|
| P0（当前） | 前 30 分钟纠偏、封神山河图、战斗 v3 | 零调试新档 25 分钟前后破真人劫；玩家能说清“我为什么修行、榜文是什么” |
| P1 | 云存档、账号、服务端权威结算、排行榜 | 双端同账号、改本地时间无效、榜单可查 |
| P2 | 势力赛季原型、365 神位、道友助战 | 一个完整赛季可玩通，神位发放与争夺闭环 |
| P3 | 金仙仪式线、封神战场、终局路线 | 不使用调试手段可玩到赛季终局 |
| P4 | 双端上架、运营活动、跨服 | 首日留存目标达到品类基准，服务器可扩容 |

## 七、风险与对策

- **放置 + 文字 + 战斗排序的复杂度风险**：前期只开放排序三卡，后期再扩展构筑；自动托管始终保留。
- **赛季重置伤害**：转世保留道痕、图鉴、外观、称号与部分牌库等级，只重置境界与经济，且赛季结算要有足够长的预告。
- **封神 IP 认知门槛**：所有系统首次出现必须用一句“封神锚点”解释（如“功德=护住真灵，劫气=更快但更危险”）。
- **外挂与脚本**：P1 起所有产出服务端结算；客户端只允许表现层缓存。
