# 8.3 战斗统一化 + 条件触发系统 + 展示层补全 验收标准 v0.1

> 生成于 2026-08-21。本批次承接 `design/8.0`（斗法栏连锁制）与用户两轮指令：
> ①「原来的战斗机制完全废除，删除全部内容，只用新的战斗机制」；
> ② 战斗展示设计参考（两血条实时变化 + 逐行战报 + 0.5s 悬念节奏 + **条件触发系统** + 半文言战报 + 败因摘要）。
> 用户原话评定：**条件触发系统性价比最高（★★★★★）**——「Boss 机制是谜面，条件配置是谜底」，玩家借此"编程"角色 AI。

---

## 一、本批次范围（对照设计完整范围逐项可核对）

### A. 废除旧卡牌战斗系统（用户硬指令）
- A1 删除 `web/js/battle-engine.js`（旧卡牌引擎，playCard/hand/AP/抽牌）。
- A2 删除孤儿遗留文件 `web/game.js`、`web/ui.js`（内含旧 BattleEngine，未被 index.html 加载）。
- A3 `index.html` 移除旧引擎 `<script>` 标签。
- A4 所有战斗类型统一走 V2：遭遇战、Boss 战、破劫、杀阵——不得有任何路径再调旧 `startBattle`。
- A5 移除 `battle_v2_enabled` 开关与 `isBattleV2/toggleBattleV2`（V2 成为唯一系统，无需开关）。
- A6 移除 `ui.js` 旧 `renderBattlePopup`（卡牌渲染器）与弹窗路由 `kind==="battle"` 分支。
- A7 全代码库无旧引擎残留引用（BattleEngine.xxx / battlePlayCard 等），`node --check` 全过。

### B. 条件触发系统（★★★★★ 核心策略层）
- B1 斗法栏条目支持 `{id, condition}` 对象，兼容旧字符串数组（归一为 condition="always"）。
- B2 引擎 `_conditionPasses(condition, battle, slotIndex)` 支持 6 类条件文法：
  `always` / `every_n:<N>` / `enemy_hp_below:<pct>` / `self_hp_below:<pct>` / `enemy_charging` / `round_gte:<N>`。
- B3 `executePlayerRound` 逐格释放前判定条件，不满足则跳过并 push `slot_wait` 事件（不报错、不崩溃）。
- B4 连锁（同系相邻×1.3）判定保持基于"配置相邻"，与条件正交，向后兼容。
- B5 配招 UI 每格新增「释放条件」下拉（`conditionOptions` 清单），改动即存盘。
- B6 战报渲染 `slot_wait`（"引而不发"），`_conditionLabel` 给出中文短标签。
- B7 存档迁移：`battle_slots` 条目归一为对象；新存档默认 starter 亦为对象。
- B8 单元 + 集成测试覆盖：15 条条件逻辑断言全过；整场战斗验证门控/等待/低血触发。

### C. 展示层补全
- C1 多敌人血条（修 P1 bug）：`_updateHealthBars` 逐一渲染所有敌人血条，败者灰显、蓄势者高亮（旧版只显示第一个活敌）。
- C2 败因摘要（P2）：败北时 `_renderDefeatSummary` 给出回合数/累计输出/累计承伤/致命一击/残敌余血 + 配招提示。
- C3 半文言战报（P2）：开战/出招/击杀/受击/蓄势/控制/灼烧/胜负/终极等关键日志改为半文言 register，数值与共鸣徽章保留。
- C4 情绪节奏：战报行入场动画（blogIn 0.35s）+ 既有敌方回合半拍延迟骨架，制造逐行悬念（不引入异步竞态）。
- C5 配招入口前置：术法面板「斗法栏·配招」常驻可点（移除 V2 开关与 disabled 门控）。
