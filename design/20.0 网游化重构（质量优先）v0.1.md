# 20.0 网游化重构（质量优先）v0.1

> 状态：进行中（Step 1 同构验证）
> 决策日期：2026-08-28
> 关系：本方案是**架构轨**的新主线，与 14.0「设计主控（决策总账）」的渲染轨（A4 四步：测试钉死→六抽屉→迁Vue→Pixi网格）并行。网游化不推翻「数据为体、画面为用」，而是把「数据为体」的逻辑层显式搬到服务端，画面层（ui.js）仍留客户端。

---

## 0. 目标

把现有单机放置修仙（逻辑跑在浏览器、存档在 localStorage）重构为**网游**：逻辑层上服务端（Node.js + Express + MongoDB），客户端只渲染 + 通信。支持账号、跨设备进度、排行榜、反作弊。

核心判断（用户原话）：**架构本身已经是分离的。"拆分"不是重写——是显式化已有边界，然后把逻辑层搬到服务端。**

### 实测确认的三个关键事实（决定 Step 1/2 可行性）
1. **battle-engine-v2.js 零 DOM**：grep `document/window/location/localStorage/fetch` 全 0。外部依赖大多带 `typeof` 守卫（`getTodayOmen`/`RealmManager`/`BossMechanicsV2`/`ResonanceSystem`/`SkillIdentity`/`Game` 均守卫）；唯一**不带守卫**的是 `num/int/str`（utils.js）与 `DataManager`（data-manager.js）——这两个必须在 Node 环境提供。
2. **save-manager.js 已是目标接口**：`loadOrCreate()`(:6) / `save(state)`(:244, localStorage.setItem) / `wipe()`(:248, localStorage.removeItem)。Step 2 只需注入化 + 加 DbSaveManager 变体。
3. **resonance-system.js:127 已有同构模板**：`if (typeof module !== "undefined" && module.exports) module.exports = ResonanceSystem;`（UMD 守卫）。如需让其它文件可被 `require`，套用此一行即可，浏览器侧无副作用。

### Step 1「0 改动」的实现方式（重要修正）
全 29 个 JS 文件**只有 resonance-system.js 有模块系统**，其余均为 `"use strict"; const X = {...}` 浏览器全局、靠 `<script>` 标签加载；且 `data-manager.js:10 loadAll()` 用浏览器 `fetch("data/...")`（相对路径，Node 原生 fetch 不解析相对路径）。因此 Step 1 **不能**裸 `require('./battle-engine-v2.js')`（无导出、缺兄弟全局）。

**采用「零源码改动」的 vm harness**（`test/harness.js`）：
- 用 `vm.createContext` 建隔离沙箱，注入浏览器全局桩（`document/window/localStorage/navigator/location`）；
- `fetch` 桩 backed by `fs`，按 web 根目录解析相对路径 → `DataManager.loadAll()` 原样可用；
- 按 `web/index.html` 的 script 顺序把逻辑层文件（剔除 DOM/UI 文件）依次 `vm.runInContext` 进同一沙箱，`const` 全局共享同一词法环境（等价于浏览器多 `<script>` 共享全局）；
- `Math.random` 替换为**可复现 LCG**（种子默认 20260828），使服务端战斗结果可重复，作为「客户端/服务端一致性」的可自动化代理验证。
- 源码 0 改动；新增仅 `test/harness.js` + `test/server-battle-test.js`。

### 依赖闭包（Step 1 实测）
逻辑层 Node 安全（顶层 0 DOM），加载顺序镜像 index.html：
`utils → constants → data-manager → realm-manager → save-manager → (unlock/event/reward/action/goal/boss/breakthrough-manager) → resonance-system → skill-identity → battle-engine-v2 → boss-mechanics-v2 → liupai-manager → gameplay-engine → content-director`。
剔除 DOM/UI：`audio-manager / battle-ui-v2 / scroll-scene / atmosphere / world-scroll / world-map / ui-constants / ui / game.js`（game.js 留待 Step 2）。

### 战斗引擎公开 API（Step 1 测试驱动用）
- `BattleEngineV2.create(state, cfg)` → 返回 battle 对象（battle-engine-v2.js:76）。
- `BattleEngineV2.runFullAuto(state, battle)` → 循环 `executeRound` 直至 `_dead` 或 `maxRounds`，返回全部 events（:780）。
- 结果读 `battle.done` / `battle.win` / `battle.round` / `battle.stats{dealt,taken,lastHit,resoBroken,resoEnhanced,resoNormal}` / `battle.playerHp` / `battle.enemies`。
- Boss cfg 镜像 `startBossBattleV2`（game.js:577）：`{ name, enemy_power: num(boss.recommended_power), adds, source:"boss", mechanic, weakness: boss.weakness||null, payload:{bossId} }`；`mechanic = boss.mechanics ? String(boss.mechanics).split(":")[0].trim() : null`。

## 5. 与 14.0 渲染轨的关系（并行不冲突）
- 14.0 §K「数据为体、画面为用」继续有效：网游化把「体」（逻辑 + state）搬服务端，「用」（ui.js 渲染）留客户端，正是该原则的延伸。
- A5「不走 Cocos/Godot，动画层 DOM/CSS/Lottie」不受影响——本方案不碰渲染/动画。
- 渲染轨 G1（测试钉死）/G7（渲染兼容）/G2（六抽屉）仍可在客户端独立推进；批次0（九Boss接线，已于 e909607 提交）属内容轨，已完成。
